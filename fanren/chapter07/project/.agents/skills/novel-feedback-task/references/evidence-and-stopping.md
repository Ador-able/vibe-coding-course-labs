# 证据与停止条件

## 先核对对象与版本

反馈至少对应具体作品、章节、要求基线和正文版本。版本不同不意味着意见全部失效，也不意味着意见仍然成立。读取当前完整对象，再核每一条原句与目标：已经处理的差距不重复修改；仍存在的差距可以按当前基线处理；没有当前依据的意见记为待确认。

人工反馈、工具检查和模型评语都可能出错。保留意见的具体依据，检查它是否真的拒绝了一种满足要求的合法结果。旧短语检查失败，不能要求把已经修正的时间改回去。不可通过修改目标、删去必要内容或更换产物来隐藏失败。

## 按问题选择信号与处理者

| 问题 | 证据与复查 | 谁处理下一步 |
| --- | --- | --- |
| 约定的编辑标记未替换 | 当前保存正文中的标记、对应修订的机械结果 | AI依据明确要求补写；宿主Hook只检查标记，不改正文 |
| 与确认事实冲突 | 当前要求中的事实与同版全文中的具体句子 | AI处理明确冲突；事实未定或要求冲突由作者决定 |
| 缺少目标场景或动作 | 完整正文与本次目标，例如是否真的发生开门、进入 | AI在授权范围补缺，作者全文复核；检索到角色名不能验收完整场景 |
| 不喜欢节奏或人物口吻 | 具体段落、作者希望的表达方向与允许改变的范围 | 作者选择；AI提出或执行有范围的修改，不自报文学评分 |
| 保存或检查失败 | 真实工具错误、宿主事件、标准错误与当前业务状态 | 先定位输入、连接或检查执行；缺信息时交给操作者，不改小说来掩盖程序失败 |

没有必要在每个任务跑完所有检查。Hook接宿主事件，Git钩子接Git事件，CI接仓库工作流事件；这段小说修订不需要运行编码构建或CI。若某项检查已有有效返回，先使用它，不重复手工启动同一检查制造第二份报告。

## 停止条件

- 当前可判断的目标已处理并保存读回：交付待审稿，说明仍需作者阅读的部分，不继续润色或扩写。
- 需要的事实在现有材料中查不到，或作者未决定的取舍会改变这轮改法：保留有效稿，提出具体缺口；不编造事实或擅改同级要求。
- 同一检查结论在修改后重复出现，但原句和问题没有变化：先核查检查对象和规则，不再重复同样修改。缺乏可解释的新办法时停下。
- 工具或检查连续失败，而当前材料没有支持新的恢复办法：保留真实失败及已保存版本，交给操作者；不能自动重试到得到想要的输出。
- 达到本轮保存次数或其他预算：停止新增修订，交出当前状态、尚存差距和下一步所需条件。

这些是提供给AI的工作方法，不是业务写入硬限制。真正的超时、取消和费用控制由所用宿主或服务提供，并需另查实际配置。会话正常结束、保存成功和标记检查通过，都不等于整篇文学合格或作者已采用。
