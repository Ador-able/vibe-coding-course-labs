# 人的决定实验

沿用仓库根目录的公共页面与模型设置，打开“05 理解工具、工作流与 Agent → 人的决定”。

1. 在“选择方向”运行任务，比较模型依据资料提出的两个开场及各自特点，作出选择后继续，核对新要求与保存正文。
2. 在“改稿与采用”阅读这份实际稿件，采用后修改正文，观察新稿回到草稿状态。展开旧版本采用请求，可以检查入口是否拒绝过时的判断对象。
3. 在“批准操作”提议保存一段原文，核对完整对象与参数后批准。批准只记录决定，点击“继续执行”才会接续实际操作。也可以在执行前修改提议，形成新的具体请求并重新判断。

“加载课堂实录”保留本篇使用的方向接续、改稿采用与动作审批记录，三个环节与自己的运行使用相同页面。课堂中的教学选择不代表读者已经采用该写法或认可稿件质量。

## 决定与实际状态

方向问题通过模型实际提出的 `ask_direction` 调用展示。人的回答对应原调用，写入当前作品要求，再作为工具结果进入原任务的后续请求。模型和工具循环由已安装 AI SDK 运行，任务消息和本轮工作区留在本机，刷新可以继续读取。

采用绑定这份工作台稿件的具体修订。修改后重新成为草稿，是本实验的业务规则；内容质量仍需人判断。

操作审批使用 AI SDK 的 `toolApproval`。每次请求保留实际 `approvalId`、`toolCallId` 与完整参数；本实验按具体请求逐次批准。撤回原请求并提交新参数后，由模型形成新的调用，不沿用旧批准。拒绝不会执行保存；接续只允许当前决定，重复或过时请求会被拒绝。

每轮记录保留工具输入输出、人的决定、关键时点的程序独立读回，以及完整模型请求与返回。取消或异常保留已发生的操作，不会撤销已经写入的稿件。没有设置输出 token 上限。

`materials.json` 包含设定摘要、C01—C03 原文与第一章大纲。C、D 是 C03 相邻原文段落的受控保存对象，不是模型生成章稿；它们用于观察参数变化与批准范围。`classroom.json` 保存本文实际使用的两个工作区记录。
