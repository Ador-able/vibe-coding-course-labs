# 工作流与 Agent 对照实验

沿用仓库根目录的公共页面和模型配置，打开“05 理解工具、工作流与 Agent → 工作流与 Agent”。

1. 选择“路径已知”或“根据线索补查”，阅读任务与工具定义，先预测每组还需要取得什么依据。
2. 点击“运行对照”，依次运行工作流、Agent 和混合方式；也可以加载本篇使用的课堂实录。
3. 对照程序预读、模型实际选择的工具和完整意见，核对具体引用，再比较用量与等待。

工作流组固定读取作品要求和第一章后分析；Agent 自行选择读取与查询；混合组预读基础材料后按需补查。三组共用同一任务、练习稿、资料与模型。工作流只是“固定基础读取”的基线，不能用它代表所有预设流程；加入固定检索、条件路由或全量读取，也可能完成补查任务。

《乌桐镇的停钟》是本节编制的教学材料，练习稿不是历史模型生成记录。练习稿一和练习稿二包含不同的待核对描写，适合尝试选择策略是否随线索改变。默认核对依据不进入模型请求或工具返回。

每次对照在本机保存独立资料快照与完整运行记录。界面只读，不修改章稿或设定；停止时保留已完成的请求与工具结果。服务错误、取消和模型未完整结束与内容判断分别展示。实验没有设置输出 token 上限，工具循环最多进行二十轮模型请求。

`classroom.json` 保留本文使用的两种情境真实对照，运行与课堂实录使用同一呈现方式。`materials.json` 包含全部教学材料、两份练习稿和单独存放的核对依据；模型只得到当前任务、程序预读以及自己实际调用返回的资料。
