# Agent 停止实验

沿用仓库根目录的公共页面与模型设置，打开“05 理解工具、工作流与 Agent → 继续、求助或停下”。入口为 `/requests/agent-stopping/`。

1. 选择情境，查看工具定义与任务，需要时修改任务或展开运行边界。
2. 运行任务，观察实际工具反馈与结束原因；在取消情境中，运行后点击“取消本轮”。
3. 对照本轮保存记录、模型汇报和程序独立读回，判断已完成什么、还缺什么。

“加载课堂实录”使用相同页面，只展示本篇实际使用的 A、B、C 与取消各一轮记录。

## 四种情境

- A：材料足够，模型根据原文、设定和第一章大纲写作、保存并读回。
- B：开篇叙事方式由作者决定。模型先读资料，自行提出两个开场与各自特点，通过 `ask_direction` 提问。等待时保留原任务、消息、问题调用标识和实际稿件状态；可以选择一个方案或填写方向，再从原任务继续。首次等待的记录仍保留在运行事件中。
- C：本轮独立 SQLite 库安装真实写入触发器，草稿保存持续失败，读取仍可用。这是课堂设置的工具环境故障，不是模型内容错误，也没有截断模型输出。记录保留实际失败及后续行动。
- 取消：初始工作区载入工具读写实验的一份真实已保存章稿，再运行修改任务。初始稿的来源文件、记录 ID 与字段位置见 `materials.json`。界面分别展示初始稿与本轮结束时的实际稿件；旧稿仍在不代表本轮产生了新稿。

## 运行边界与实际状态

工具循环由已安装 AI SDK 的 `generateText` 完成，`stepCountIs` 默认限制为 16 次模型调用，不是 16 次工具调用。可以在页面调整调用上限，或设置整轮时限；时限为 0 时不设置时间限制。B 回答后的接续仍使用原有预算，调用次数与实际运行时间累计，等待人的时间不计入运行时限。没有设置输出 token 上限，不自动重试模型服务请求。

模型自然结束、等待作者、工具阻塞、达到运行边界、用户取消和服务异常分别记录。达到上限不等于任务完成。草稿完整保存且模型读取了相同实际内容后，页面才标记保存与读回已完成；内容是否合适仍需人阅读判断。

取消通过 `AbortSignal` 中止后续请求和工具执行。写入前检查信号，已经提交的数据库事务保留；取消不会撤回已保存的稿件。服务异常同样保留实际副作用。结束后程序关闭工作连接，再独立打开数据库读回。

## 材料和本机记录

`materials.json` 保留 C01—C03 完整原文、设定摘要、第一章大纲及取消情境的既有稿来源。每轮在本机数据目录的 `agent-stopping/<本轮ID>/` 保存 `run.json` 与 `work.sqlite`；页面刷新后可以读回当前情境的本机记录。服务中断的运行会标记为中断，不自动重新调用模型。

接口位于 `/api/agent-stopping`：`GET /materials`、`GET /current?scenario=A`、`POST /run`、`GET /runs/:id`、`POST /runs/:id/answer`、`POST /runs/:id/cancel` 与 `GET /classroom`。运行参数包含 `scenario`、`task`、`limits: { maxSteps: 16, maxSeconds: 0 }`。回答绑定当前问题的 `toolCallId`，传入 `choice` 或 `answer` 中的一项。

`classroom.json` 的结构为 `{ "version": 1, "runs": { "A": 真实运行记录, "B": 真实运行记录, "C": 真实运行记录, "cancel": 真实运行记录 } }`。只放实际完成录制的原始记录，不用空对象或编造结果替代真实运行。
