# 工具与 Agent

从读取资料、生成草稿、实际保存和工具反馈，理解模型怎样连接外部系统并持续推进任务。

## 工具读写

沿用仓库根目录的公共页面和模型配置，打开[工具读写实验](/requests/tools/)。先根据任务选择工具集，运行任务或加载课堂实录，再核对实际工具调用与保存结果。

## 工具反馈

打开[工具反馈实验](/requests/tool-results/)，使用同一页面运行自己的任务或加载本节课堂实录。

1. 查看工具定义与任务，预测需要取得哪些信息。
2. 运行任务；也可以在“任务依据与当前前文”中调整第一章正文，再观察后续行动。
3. 按模型请求轮次查看实际收到的工具反馈、提出的调用与执行结果，最后核对程序独立读回的第二章。

每次运行使用独立工作区，第一章的编辑会实际写入该工作区。完整请求、工具结果与草稿保留在本机运行记录中；课堂实录来自同样的真实流程。

## 比较谁来安排读取

打开“控制方式实录.html”，查看凡人第一章的五种读取安排，以及空稿和作品不存在的分支。完整输入、公开事件、运行前后对象与回答保存在“课堂记录/凡人原文-20261015/03-控制方式”和对应的 `runs/control` 目录。

第三节先比较两种方式：应用按固定顺序读取，或由 Agent 决定读取。两次均使用同一份真实第一章，每次自动建立独立练习库：

```powershell
pnpm compare --case existing --mode serial --cancel-after-ms 180000
pnpm compare --case existing --mode agent --cancel-after-ms 180000
```

对照终端给出的记录目录，看谁读取了什么、模型是否取得全文，以及数据库是否保持原样。其他方式 `routed`、`concurrent`、`mixed`，以及空稿 `empty`、缺失作品 `missing-work`，可按课程需要单独选择；每次只运行指定的一组。

## 人的决定怎样进入下一轮

“人的决定实录.html”保留方向提问、要求更新、受控改稿与采用、后章接续，以及独立审批入口的完整记录。编者通过CLI进行的教学决定有明确标记，不表示用户已经选择方向或认可文学品质。

第四节使用一个尚未选定叙事切入的新练习库：

```powershell
node 准备实验.mjs 04
pnpm agent --db data/04/novel.sqlite --chapter 1 --cancel-after-ms 180000
pnpm lab chapter 1 --db data/04/novel.sqlite
```

读实际问题和当前章稿。若需要人的方向，查看 `materials/第四节方向.json`，作出选择后先预览，再写入。例如选择 B：

```powershell
node scripts/记录第四节方向.mjs --choice B
node scripts/记录第四节方向.mjs --choice B --apply
```

把第一轮终端返回的任务编号交给编码助手，用 `--resume-task` 接续同一练习库的第一章。随后独立读回，核对 Agent 是否真正读到并使用了人的新决定。

人工改稿与采用沿用 `lab save`、`lab adopt`：先通读实际正文，再让助手按当前修订保存完整改稿。改变正文后应重新判断是否采用；采用决定只对应那份具体稿件。

### 选做：审批一次具体保存

动作审批使用另一个练习库，模型沿用请求观察室已保存的设置：

```powershell
node 准备实验.mjs 04-审批
pnpm approval propose materials/保存动作A.json
```

完整核读返回的待决正文与参数，再把自己的批准或拒绝交给助手。助手使用返回的任务编号和 `approvalId` 记录决定、接续；不要省去这次具体决定。独立检查保存结果：

```powershell
pnpm lab chapter 1 --db data/04-审批/novel.sqlite
```

`materials/保存动作A.json` 与 B 是C03原文摘录，B多保留相邻一段，用于观察完整保存参数变化，不是模型生成记录。它们只允许保存本地草稿；内容采用和发布属于另外的决定。

这轮提议A时，模型更换了原文引号，入口以 `ACTION_MISMATCH` 停止，章稿未写入。另一个独立条件使用C03不含引号的相邻叙述段C、D，观察拒绝、改参和批准后执行；命令中的材料名可改为 `materials/保存动作C.json` 或 D。不要修改既有失败记录、放宽参数相等要求，或反复提议直到出现理想回答。

## 查原文还是问人

`clarification/original.md` 是现成小说的完整C03片段，`clarification/tasks/a.md` 至 d 是四种短任务。主练习只需将同一份原文和选定任务提供给已有AI工具，不必续写完整章节。

需要保存实际请求时，复用共用模型设置与当前依赖：

```powershell
node ../../../scripts/run-lab.mjs . clarification/run.mjs --case a
```

其他条件只替换末尾字母，不必全跑。结果在 `clarification/records`，原文与任务直接进入请求，入口没有文件读取工具，也不保存小说章稿。错误保留在同轮报告中，不自动重试。

“查资料还是问人实录.html”对应完整实际回复。首轮A/D因1400输出上限而没有最终文本；提高上限后仅各补一次，原记录保留。D随后直接交出包含“正午”的摘要，没有先处理同级冲突；C提出重点选择，但截止地点的表述仍需回原句核对。

## 观察何时继续、求助或停下

“停止条件实录.html”对照材料足够、方向未决与受控写入故障。A、B复用前课已保存的真实记录，本轮只新增C和5秒取消各一次；完整原件与独立读回索引在“课堂记录/凡人原文-20261015/05-停止条件”。

先选一个条件。A 的材料足够，B 尚缺人的叙事切入决定，C 会发生真实的草稿写入失败。下面只准备并运行 C：

```powershell
node 准备实验.mjs 05-C
pnpm agent --db data/05-C/novel.sqlite --chapter 1 --cancel-after-ms 180000
pnpm lab chapter 1 --db data/05-C/novel.sqlite
```

对照运行记录和独立读回结果，判断本轮实际保存了什么、为什么停止、还缺什么。非零退出码可能表示未保存、失败或取消，具体原因要看记录。

想观察另一个条件时，把三条命令中的 `05-C` 改为 `05-A` 或 `05-B`；每次只准备指定条件。已有数据库不覆盖，其他条件也无需重新运行。沿用已有登录与依赖，不必切换代码或重装。

如需观察取消，在已经保存过草稿的练习库中另起一轮，把取消时间改为 `5000`，再独立读回。旧稿仍在不表示本轮完成；取消也不能撤销已经发生的保存。
