# 当前稿与新任务的文件交接

材料统一使用《凡人修仙传》完整C03和摘要比较页的真实两案。只整理短笔记，不续写小说。`materials/before`保留待选状态，`materials/after`保留编者教学选择、92字当前稿和只交两项问题的新任务；小说原文未改。

主练习可直接将完整文件上传或粘贴到已有AI助手，先等待选择，再保存自己的笔记、任务与决定，交回全文。能否接续，要核对实际取得的材料和完整回答。

已完成统一安装的读者，可选用项目锁定的Codex SDK记录一次文件工具交接：

```powershell
node handoff/run.mjs read
```

终端给出本次记录目录，其中`current`是练习工作对象。先查看公开工具事件和回答；读取失败时保留结果，改用工具实际能取得全文的上传或粘贴入口。没有取得材料就不继续声称交接成功。

取得材料后，将自己的当前摘要保存到`current/notes.md`，任务保存到`current/current-task.md`，决定保存到`current/human-decision.md`；保留原文与旧方案。接续时使用同一个记录目录：

```powershell
node handoff/run.mjs continue handoff/records/实际待选轮目录
```

程序在每轮发出前冻结完整文件与提示，并记录公开事件、回答和运行期间文件是否变化。`report.completed`只表示Harness轮次结束，不能代替文件读取成功或产物合格的判断。

本次课堂的两轮只读命令都因沙箱初始化失败，未取得材料。完整记录与独立核对保留在`records`，实录页为项目目录中的`文件交接失败实录.html`；没有修改本机沙箱设置。另一个网页共写实验通过实际请求直接提供全文，其记录在请求观察室仓库，属于独立对话。
