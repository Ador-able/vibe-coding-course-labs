# 渐进式信息披露

共用服务启动后，打开“请求与上下文 → 渐进式信息披露”。使用页面顶部的模型设置。

资料设计与图文跟读见[教学](../教学.md)。

首次提供 `创作资料/全书入口.md` 与 `当前工作.md`，再按本场需要展开人物、地点、物品工作卡、详情与章节原文。选择“逐层读取”，点击“运行实验”，展开实际披露过程和运行记录。

实现位于 `labs/requests/src/disclosure/`：

- `materials.ts` 从现有文件读取全文，按固定清单核对哈希。
- `flow.ts` 的 `initialMessages` 放任务、全书入口与当前工作。详细资料由模型选择路径，实际读取后加入下一次请求。
- `routes.ts` 沿用公共模型设置，将本次输入、返回、读取结果和哈希保存在 `.data/disclosure/novel/`。

先检查第一次请求没有人物、场景档案与原文全文，再核对每次读取的内容何时出现在后续输入中。写出草稿本身不能证明发生了逐层读取。

“提供全文”一次提供全部创作资料；“只提供本次摘要”仅从 30 条小说原文生成当前进度的摘要，再用新会话续写，不附工作卡、设定档案、原文或读取工具。每个条件独立构造消息，失败不自动重试。

这里只学习资料分层与按需纳入上下文，后续小说插件实践会接入成熟 Harness。
