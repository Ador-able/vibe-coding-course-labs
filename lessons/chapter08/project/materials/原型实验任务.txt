　　下面是供课堂复现和独立核对的人工整理提示，不是小说模型运行输入。让能读取文件和运行本地程序的助手在同一实验目录工作；如果不能操作浏览器，就如实保留这部分未查范围。
本轮目的是验证一种人工读稿、改稿入口，帮助我们决定下一步工作。课程练习载体是小说工作台；前置目标仍是交付三章待审草稿，沿用 CLI，当前没有把网页、多用户协作或自动发布变成已确认需求。

请先完整读取 README.md、materials/作品.json、materials/第一章.md、materials/第二章.md、materials/第三章.md、src/store.ts、src/schemas.ts、src/cli.ts、src/prototype-http.ts、prototype/index.html、prototype/app.js 与 prototype/app.css。沿用已有 Store、CLI、MCP 和成熟 Harness；不要新造模型工具循环或第二份持久业务状态。本轮不调用小说生成模型，不运行 plugin:add，不修改父项目或全局配置。

先给出每项待验证问题、改变的条件、预期结果和需要保留的证据。再在独立实验库的 fanren 作品执行。初始化只取 materials 中的完整资料和三章正文，经 Store 人工保存为本轮 r1 草稿，不复制历史任务、采用状态或修订，不称新生成。

依次检查：
1. 页面初始三章全文与初始化材料逐字相同。第2章追加“【编者注：C04包含考核结果，交付前按原文核对。】”，保存后真实重新读取。核对完整正文、修订、状态和来源，并从 CLI 与官方 MCP Client 读同一库。
2. 两个窗口都先读第2章r1。一个保存成为r2；旧窗口追加“【旧窗口校订：保留正午前到崖顶的考核条件。】”并提交。保留真实冲突返回，确认当前稿未被覆盖、本地全文仍在，读取当前稿后两份可分别对照。不自动合并，不用状态字段代替内容判断。
3. 给本标签真实请求增加2500毫秒受控延迟。保存等待时提交文本输入尝试“等待期间不应进入正文的文字。”，核对章名和正文不可编辑、尝试文字未进入；保存并读回后恢复编辑。不要替换接口返回来冒充真实保存。
4. 实际断网提交，记录请求失败。核对结果未确认、全文保留、字段恢复编辑，再追加“失败后可以继续编辑。”。此时不能直接再次保存；恢复连接后读回服务当前稿，确认本地与存储稿分别保留。不要推断写入中断自动撤回。
5. 三种方向 original、desk、notes 保持同一文案、三章正文、字段、必要操作、1265×714 CSS 视口及相同缩放，读回实际视口尺寸；在390×844观察窄屏。保留完整页面与等待、失败、冲突、对照的关键状态。图片使用原生高分辨率输出；页面导出和根据记录整理的实录图分别标明，不冒称截图。分别记录功能是否正确、位置和操作是否易辨、整体口吻由哪些关系形成及其代价。原版可以胜出，最终方向由使用者选择。
6. 运行 scripts/observe-reminder.mjs，将反馈后24小时的边界、暂停与新反馈条件逐项对照。声明它是独立教学构造规则，没有发送提醒，也不进入正常小说页面。
