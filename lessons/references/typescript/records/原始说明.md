# 运行速查完整练习材料

这是《TypeScript 与项目运行速查》的独立命令行练习。人工段落、完整源文件、锁文件、Git 记录与九次本机观察均保留。没有模型调用、Agent、图形界面或生产数据库。

## 查看与恢复

`项目源码/` 是固定完成点的完整源码快照，便于直接阅读。`原始观察/` 保存实际参数、工作目录、全部 stdout/stderr、退出码及真实保存文件。它们包含原执行路径；在你的电脑上复做时，路径与记录标识会变化，需比较对应关系和完整内容。

从解压目录克隆自有 Git 项目，不要把上层仓库的版本当作练习版本。以下命令用于 Windows PowerShell，每行依次执行；目标 runtime-reference 应为尚不存在的新目录。

```powershell
git clone ./教学记录.bundle ./runtime-reference
Set-Location -LiteralPath ./runtime-reference
git rev-parse --show-toplevel
git rev-parse HEAD
node --version
pnpm --version
pnpm install --frozen-lockfile
pnpm check
pnpm observe
```

项目应显示包名 `ai-runtime-reference`；实际环境为 Windows、Node24.12.0、pnpm11.20.0。固定起点 `669c580d9d78cfc407ca04a8453f2b4e8cf4825a`，标签 `vcr-01-start`；固定完成点 `ce16cfe937ab20d0b0a15f697c3ee8cb5057b99d`，标签 `vcr-01-complete`。完成点的业务代码和输入与起点相同。安装需要访问已配置包源，观察不调用网络服务或模型。没有在这份记录里验证 WSL、Linux、浏览器或交互登录。

观察器会写自己的 `output/草稿.json` 和一份新的 `runs/<记录标识>/完整观察.json`。九条子进程预期状态依次为 `0,1,0,1,0,0,0,0,0`，两项失败是有意的教学输入，不是通过观察器退出码自动判定正确。比较全部输入、字段错误、保存读回、路径、环境和编码输出，不能只数九条记录。

本次写失败把已存在的文件当成目录，旧文件全文不变，不保证覆盖途中故障总能回滚。未设置演示环境变量有记录器先清该子环境键的前提。默认材料按模块位置定位；显式相对参数按工作目录解释。JSON/type 正确与文件保存成功不能证明文学质量或人的采用。

`文件清单.json` 列出除清单自身外的全部包内成员、字节数和 SHA-256。源文件保留实际字节，Git bundle 只包含本练习的两次提交，不含其他项目或私有上下文。

`教学材料/` 保留正文所用的完整联合状态示意、CSV 示意和排错提示；它们是教师构造材料，没有执行新的模型任务或 CSV 解析。CSV 正文字段特意包含 ASCII 逗号与换行，均属于同一个加引号的字段。排错提示所列失败来自直接执行 Node 的真实记录。
