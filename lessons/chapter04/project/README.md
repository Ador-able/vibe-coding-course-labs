# 任务与结果检查

沿用仓库根目录启动的课程实验，在“请求与上下文”中选择本节实验。右上角的模型设置共用，只需填写 OpenAI 兼容 API 地址、密钥和型号。

| 本节关注什么 | 实验入口 | 对应实现 |
| --- | --- | --- |
| 用途、事实、写法与交付怎样变成判断依据 | [任务验收](http://127.0.0.1:4318/requests/task-goals/) | `labs/requests/src/tasks/materials.ts`、`checks.ts` |
| 固定任务，单独改变样例 | [样例对照](http://127.0.0.1:4318/requests/task-examples/) | `materials.ts` 的样例分支 |
| 指定改动与全文保留怎样一起核对 | [局部反馈](http://127.0.0.1:4318/requests/task-feedback/) | `materials.ts` 的反馈分支、`checks.ts` |
| 固定样本、方法与判断条件 | [评估样本](http://127.0.0.1:4318/requests/task-evaluation/) | `contract.ts` 的 `PLAN`、`materials.ts` 的 `criteria` |
| 同一初稿的两条路径怎样统计消耗 | [合格率与总成本](http://127.0.0.1:4318/requests/task-cost/) | `checks.ts` 的 `totals`、`routes.ts` 的父记录关联 |

1. 展开“本节输入与判断条件”，先看用途、完整任务和本轮改变的条件。
2. 点击运行，得到真实模型返回；按原句与资料逐项填写判断。字数检查和局部替换对比由程序完成，情节与文学效果需要阅读。
3. 展开“实际请求与返回”，回查实际发出的消息、返回、结束原因、等待与用量；可导出本轮记录。失败保留，不自动重跑。

## 调用与记录

网页 → `/api/tasks/run` → `buildPrompt` 组织本节材料 → 共用 API 调用 → 保存实际请求与返回 → 程序检查与人工核对。

每次调用独立保存到仓库根目录的 `.data/tasks/`，刷新后可以继续查看。超时或取消也保存已取得的返回与用量；页面不会把没有返回的字段当成零。取消后若网络连接已断开，刷新运行记录查看最终状态。

若结束原因为 `length` 且没有正文，先查看返回的推理用量。接口支持时，可在“调用设置”中选择较低推理档位，再开启新一轮；原来的失败保留。推理档位在这五节中共用本机偏好，同一轮内固定，默认不发送此参数。

样例对照进行三次独立调用，评估样本进行五次独立调用。成本实验进行一次初稿与一次核对，A、B 共享初稿；按路径比较时 B 包含两次调用，但整轮只发生两次调用。事实判断尚未填写时保持待核，不计为合格。

## 课堂实录

五份实录 HTML 及其资料、输入和运行记录保留当时内容。页面的“查看课堂实录”用于阅读这些历史返回；新运行使用网页中的 API 设置，记录另存。

网页局部反馈截图对应的 [API 完整记录](http://127.0.0.1:4318/requests/records/tasks/feedback-api-20261021.json) 保存这次实际发出的请求、服务返回、用量与全文替换检查；它与历史实录分别存放。
