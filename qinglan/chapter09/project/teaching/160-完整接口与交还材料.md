# 分开修改以后，结果能否接起来

本文件全部是教师构造材料，没有已开发应用、真实模型调用或运行回执。字段是这份练习的约定，不是现有小说 Store 或 MCP 工具的 API。

## 当前目标

制作小说工作台的正文查阅页面。用户已经选择《青岚修仙录》，输入“合窗以后，林青记录了什么”；结果仅来自该作品。每项结果让用户看见章节标题、段落位置与完整段落，并能打开对应原文。生成摘要可以附加，不能代替原文。

本次共同输入是以下完整段落：

作品：《青岚修仙录》

第三章：《合窗以后》

正文第 10 段（不计标题；对应材料文件第 21 行）：

> 林青在新纸上记下“合窗，书页起，未见四折纸动”。他原本想写“风已停，书仍动”，落笔前又把“风已停”几个字划掉。窗合了，纸没动，都不能替他量出案面上的每一缕气流。况且刚才也没有看清究竟是什么使书页起来。

原文入口：exercise-qinglan:chapter-3:paragraph-10。这个字符串只表示课堂原文编号，没有对应网站或可打开的远程页面。

## 共同接口 v1

1. 查询部分向显示部分交回一个对象。对象的 results 是列表，没有结果时为空列表。
2. 每项结果包含 chapterTitle（章节标题）、paragraphNumber（段落编号）、sourceText（原段落全文）、sourceReference（原文入口）。显示部分依据这四项显示内容与入口。
3. chapterTitle 和 sourceText 保留原文字；不能把生成摘要放进 sourceText。
4. 当前选定作品必须用于查询范围。结果数量多不等于查询符合要求。
5. 接口改变由主任务统一决定，两方都收到同一版本后再接续。任何一方不能只在自己的文件中改字段名，就认为对方会自动适配。
6. 结果结构符合只是交付的一部分；还需核作品范围、原文和入口是否对应。

## 工作归属与依赖

正文查询者只负责“练习项目/src/query.ts”；页面显示者只负责“练习项目/src/results.ts”。这两个路径是设想的职责位置，本章不会创建它们。共同接口在两项工作开始前确定，接口说明由主任务维护，两方不各改一份。两项工作可以各用上述固定段落先准备各自部分；把实际返回交到显示入口的整体检查，必须等相应产物返回。

允许独立修改两个文件，不意味着整体独立：返回的列表位置、字段含义、作品条件和原文入口都跨越两个部分。同一文件要由谁修改，应先分清职责或串行安排；采用独立工作区可以减少同时写文件的问题，仍不能自动解决接口和业务判断不一致。

## 正文查询部分的交还卡

修改范围：只改了自己负责的查询文件。

自述：已能得到一个含原文的对象，本部分完成。

给显示部分的完整返回示例：

```plaintext
{
  "items": [
    {
      "title": "合窗以后",
      "position": 10,
      "text": "林青在新纸上记下“合窗，书页起，未见四折纸动”。他原本想写“风已停，书仍动”，落笔前又把“风已停”几个字划掉。窗合了，纸没动，都不能替他量出案面上的每一缕气流。况且刚才也没有看清究竟是什么使书页起来。",
      "reference": "exercise-qinglan:chapter-3:paragraph-10"
    }
  ]
}
```

未提供的证据：是否只查当前作品，以及把这个实际对象交给显示入口后的结果。

## 页面显示部分的交还卡

修改范围：只改了自己负责的显示文件。

自述：用自己的样例能够显示标题、段落和原文，本部分完成。

它使用的完整样例：

```plaintext
{
  "results": [
    {
      "chapterTitle": "合窗以后",
      "paragraphNumber": 10,
      "sourceText": "林青在新纸上记下“合窗，书页起，未见四折纸动”。他原本想写“风已停，书仍动”，落笔前又把“风已停”几个字划掉。窗合了，纸没动，都不能替他量出案面上的每一缕气流。况且刚才也没有看清究竟是什么使书页起来。",
      "sourceReference": "exercise-qinglan:chapter-3:paragraph-10"
    }
  ]
}
```

未提供的证据：显示部分是否接受查询者交回的 items 对象，以及用户能否从实际查询结果打开正确原文。

## 主任务要作出的判断

不能仅因两个文件没有互相覆盖、两方都说完成，就宣布正文查阅页面通过。先对照同一个接口和完整返回：列表键名、四个字段名不一致。显示样例符合共同接口，但它不是查询者交回的实际对象。本材料足以判断这项交接不符合约定，不能据此声称某个真实页面已崩溃或修好了。

请给出一份接续安排：谁修改什么、哪项决定要同时交给两方，以及完整链路怎样检验。完成条件至少覆盖“所选作品→查询→实际结果对象→显示章节标题/段落/原文→打开对应原文”。字段对齐后，仍要核过滤条件和原文对应；此处未提供的范围证据需要补齐，不把一个正确样例当成整项完成。

同一目标也可以先串行做好一条真实链路，再拆下一项独立改动。这个小问题不要求为了并行去实现复杂框架，亦不要求学员学习整个前后端开发课程。
