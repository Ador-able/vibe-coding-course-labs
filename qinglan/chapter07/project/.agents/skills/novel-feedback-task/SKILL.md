# 处理局部草稿反馈

## 取得当前对象

读取本次反馈及其作品、章节、要求修订和正文修订。通过 novel_lab 的 read_work、list_chapters、read_chapter 取得当前要求和完整正文，不以旧报告或聊天概述替代。任务已限定范围时沿用范围，只有方向确实未定才补充计划。

## 判断这次应处理什么

把每项意见放回当前全文和要求，区分事实冲突、目标缺口、表达取舍与检查失败。旧反馈不直接用于当前稿：核对对应原句是否仍存在、差距是否仍成立，已修正的问题保留，必要时请人确认。遇到报告版本不同、检查与正文矛盾或需要停下时，读取 [证据与停止条件](references/evidence-and-stopping.md)。

为当前问题选择有用的证据。约定标记可依据保存后的真实机械检查；事实关系和情节衔接需要对照当前要求与全文；表达取舍交给作者。不要为了让报告变绿改变既定目标，不使用自评分代替检查。

## 在约定范围修改

只处理仍成立、已经授权的差距，保留本轮不涉及的文字和已满足条件。资料可查就重读；资料没有给出的事实、同级要求冲突或作者未决定的方向，不自行写成确认信息。局部补写可以提出创作细节，交付时区分提议与已确认事实。

保存前使用刚取得的作品、目标章和必要前文基线。通过 save_draft 保存完整标题与正文为草稿。出现修订冲突，先重读并判断反馈是否还适用，不把旧稿覆盖回去。不要手工编辑数据库或调用人工采用入口。

## 依据真实结果复查

保存后接收本次宿主实际提供的检查反馈，核对作品、章节和保存修订。Hook 没有产生有效反馈时记为缺检查，不把没有报错改称通过。检查没有标记，只能说明这个文字条件。

用 read_chapter 读回实际完整正文，核对本次改动、保留范围、要求修订和草稿状态；必要时查 list_chapters。若还有可判断的差距，且任务预算允许，可以作有限修正并再次保存读回。不能仅因为报告曾失败，就继续重复同样动作。

## 交付或停下

按本次请求的保存次数、范围与预算收尾。没有进展、同一失败反复、资料或方向缺失时，保留当前有效成果和真实反馈，说明继续需要什么，交给人处理。只报告实际保存修订、具体改动、未处理项与检查的覆盖范围；文学表现和稿件采用仍由作者判断。
