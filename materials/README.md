## 接收者真正开始前

沿前置章节已有的自己的n8n课堂实例，按01目录README恢复固定代码，并绑定自己新建的任务与反馈表。Git只恢复配置与材料，不恢复n8n实例账号、数据卷或凭据。原课堂表/工作流ID用于核查历史记录，不能跨实例直接当成自己的对象。不向课程共用实例或真实业务表反复提交样例。

维护者先填任务卡的正式URL、workflowId、已发布versionId、两表查看位置、账号/请求权限和联系渠道。入口应由实际接收者可访问；维护者的localhost并不是另一台电脑上的同一服务。必要条件未准备好，验收记录填写“阻塞”。本章不新增部署、登录或通知配置，也不在包中提供私有口令、Cookie或API密钥。

准备完成以后，接收者用自己实际身份，按维护者已准备的提交方式只提交“教学材料/接收者教师输入.json”一次。它是完整7字段课堂材料、failTask为布尔false；维护者应先确认eventId尚未使用。记录实际响应，按eventId查Task七个原输入字段、状态和本次executionId，再查Feedback六个原字段以及taskRowId与Task的关联。failTask只在Task，不要求Feedback增加该字段。

关闭记录页并重新打开，读回同一任务和反馈全文；只核接收端重开，不称原模型或服务器恢复。未知响应先查同一事件，已经可能生效的业务不盲目重发。模板没有通知，实际应记not_sent；若任务另含通知，需要自己的指定接收端实际出现记录，提示音/设备条件另查。当前任务卡没有真实接收者执行结果。
