# 资源、提示与插件实验

这个阶段沿用现有三章和同一 SQLite 业务状态，不建设工作台界面。运行环境仍为项目锁定的 Codex SDK/CLI 0.160.0、MCP SDK 1.31.0 与 Node.js 24.12.0。

## 资源和提示各返回什么

服务提供两个资源模板：`novel://works/{workId}/requirements` 和 `novel://works/{workId}/chapters/{chapterNumber}`。资源目录列出真实作品和已保存章节；读取回调查询当前数据库。章节不存在时返回协议错误，不制造空白正文。

`review_chapter` 返回一条检查方法及当前要求、前文和目标章的资料快照。它不调用模型，也不改变稿件或采用状态。取得之后又发生改稿时，旧提示中的材料不会自行更新，应重新读取。

```powershell
pnpm mcp:inspect --chapter 3 --output data/资源与提示.json
```

独立官方客户端实际读取了作品资料 r2 与三章 r3/r1/r1，列出 4 个工具、4 个资源、2 个资源模板和 1 个提示；取得第 3 章提示时返回 5 条消息：检查方法、当前要求、三章资料。原始结果在 `evidence/03-资源提示与插件/资源与提示实际读取.json`。

同一连接再次读取会取得新资料这一行为，另由临时数据库测试验证：预置要求从 r1 更新至 r2，原连接重新读取资源即得到 r2。测试也检查取得提示不改状态。这是预置数据实验，没有模型生成。资源目录和提示目录存在，不证明任何宿主已经自动把它们交给模型。

## 官方插件装载与真实读取

插件将 `novel-chapter-task` Skill、状态与检查参考、同一 MCP 启动入口组合。`plugin:prepare` 写入本地构建与数据库的绝对路径；绑定不进入 Git，也不含认证。官方安装会把它复制到插件缓存，所以独立 worktree 要准备自己的绑定，再安装自己的副本。

```powershell
pnpm plugin:prepare
pnpm plugin:add --output data/插件安装回执.json
try {
  pnpm plugin:check --chapter 3
} finally {
  pnpm plugin:remove --output data/插件移除回执.json
}
```

这轮临时实验开始前确认 `novel-practice@novel-agent-lab` 尚未安装、没有用户配置条目或缓存。安装只新增这个插件的 `enabled=true`；本轮 marketplace 位置通过命令参数指定，不登记全局 marketplace。官方移除删除这个插件的缓存与用户条目。没有整体覆盖配置，也没有复制、读取或输出认证文件。

首次未安装时，宿主检查实际得到 `unknown MCP server novel_lab`。它只能读仓库中的 Skill 源文件，没有取得业务资料；该失败仍保存在 `未安装宿主检查`。目录中的 available 不能作为接通证据。

实际通过的检查标识为 `b8f183d8-a8eb-4380-a287-f0a3c4b618ce`，Harness 会话为 `01a0fc1b-c223-75b0-a984-11c3aa336741`，运行记录代码版本为 `9447946`。宿主执行 PowerShell 读取官方安装缓存中的 Skill 与参考全文，再通过 `novel_lab` 调用 `read_work`、`list_chapters` 和三次 `read_chapter`。工具返回的要求、目标章修订与完整正文均和独立数据库读取相同。检查前后的要求和全部章节未变化。

模型给出了指向原文的阅读判断，正确区分作者演示的采用状态与真实用户的文学认可；阅读判断仍需主编独立审核。保存状态和修订比对不代替文学品质。

当前插件实测限于读取。直接插件调用没有普通 `agent` 入口的业务任务关联；插件写入、取消和接续没有在这轮测过。完整生成与保存使用前两阶段已验证的 `agent` 入口。

## 配置与撤销的实际范围

当前宿主的 `config/read` 表明：本实验项目的 `.codex/config.toml` 层因未登记为 trusted project 而未启用。因此不能以文件写着 `enabled=false` 推断实际已经停用。没有为此改变用户全局信任设置。

同一宿主的两次配置读取，分别传入本轮 `enabled=false` 与 `enabled=true`，有效条目分别得到 false 与 true，来源为 `sessionFlags`。普通 `agent` 入口显式停用这个插件，插件检查入口显式启用；不依赖未加载的项目配置。原始过滤结果保存在三个 `插件配置实际加载-*.json`，只包含本插件条目、相关层及来源。

Windows 在本轮检查结束后短暂占用缓存，官方移除实际返回 `os error 32`。归档本轮检查会话后，官方再次移除成功。这里记录执行顺序，不据此认定是哪一个进程或文件句柄造成占用。检查入口会记录自己的归档结果；移除失败仍需按反馈检查并重试，不手工删除全局缓存。

最终核查得到：本插件用户条目缺失、缓存不存在，整个配置文件的原始 SHA256 与排除本插件后的语义哈希均和安装前相同。基线文件只保存指纹与本插件条目，没有复制配置正文。平台独立数据目录仍存在：

`C:/Users/32686/.codex/plugins/data/agent-plugins/b8e6cc680d82427484923f728aeadd30d525dd139202bb1b301c34749a60b71d`

官方移除未承诺删除这个目录，本轮保留它；业务数据库仍在仓库中。归档和卸载各自的结果与原始失败均保存在 `安装与撤销-最终核查`。

冻结依赖安装、构建及 3 项核心测试通过。主编仍需从固定代码独立完成安装、检查与撤销；作者自审和本文记录不代替该验收。
