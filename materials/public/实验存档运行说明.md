# 三种协作入口课程实验

本存档包含已有小说业务、官方 MCP 服务、锁定依赖及本章纯客户端观察。实验不调用模型，不需要模型账户，不安装插件，不改变全局配置。人工材料和人工更新由本地脚本明确准备，每次执行都使用新的教学数据库。

环境：Git、Node.js 24.12.0 或同系列更新版本、pnpm 11.20.0。本章固定 MCP SDK 1.31.0；作者运行实际协商协议为 2025-11-25。当前文档与其他宿主不能代替实际协议记录。

在独立文件夹解压后执行：

```powershell
git clone "三种协作入口课程存档.bundle" "mcp-entries-lab"
Set-Location -LiteralPath "mcp-entries-lab"
git switch --detach vcm-08-03-end
$packageName = (Get-Content -LiteralPath "package.json" -Raw | ConvertFrom-Json).name
if ($packageName -ne "agent-practice-lab" -or -not (Test-Path -LiteralPath "pnpm-workspace.yaml")) { throw "请进入课程实验目录" }
pnpm install --frozen-lockfile
pnpm build
pnpm mcp:entries
```

固定起点 `vcm-08-03-start` 是已有服务的 `agent-practice-03-end`，提交 `3c6dde16004469f3fc36ba417804a65880ee43e5`。观察入口在实现提交 `3a6db6d` 中；固定运行版本 `vcm-08-03-end` 为提交 `6137fb197cf5ae09d48f9d2a828bca9d783ea25f`，另保存作者本轮原始证据。起点与终点的业务服务相同，新增观察脚本只负责调用官方客户端及独立核对。

本次输出目录由命令报告给出，位于 `runs/mcp-entries/<UUID>/`。先看 `complete-objects.json` 的完整内容和 `calls.json` 的参数、反馈，再看 `protocol.jsonl` 及业务表快照；`report.json` 只是定位和核对结果。作者原件位于 `evidence/08-03-三种入口/作者纯客户端观察/`，实际运行代码提交保存在 `input.json`。

预期现象：资源、读取工具与检查提示包含同一份要求修订1；提示还包含检查方法和完整章稿。第二章尚未保存，工具返回 `result:null`，资源与检查提示报该章正文尚未保存；提示缺少必需章号时报参数错误。人工增加核对委托信编号的要求后，新读取的资源与新取得的提示包含要求修订2，旧提示仍保留修订1。观察A和观察B分别核对五张完整业务表未发生变化，人工更新是两段观察之间的真实写入。

非预期错误或内容不一致时，命令非零退出并保留原件。不要删掉错误记录后只看另一次成功报告。再次执行会生成新 UUID，不覆盖先前失败。
