# Agent 任务教学实验存档

这个实验借助成熟的 Codex Harness 读取作品要求、生成一章草稿、通过 MCP 保存并读回。小说用来观察工具、上下文、人的改稿和接续，不要求开发小说产品。模型与工具的循环由 Codex 提供。

压缩包只有本说明和 Git bundle。bundle 保留源代码、依赖锁与真实 Git 历史，包括仓库中已经跟踪的受控教学运行证据；其中的公开 SDK 事件可能包含实验任务与会话标识。没有 Codex 内部会话目录、实际运行数据库、依赖安装目录、插件安装缓存、本机绑定或认证文件。

## 从存档建立仓库

需要 Git、Node.js 24.12.0 或同系列更新版本、pnpm 11.20.0，以及正常可用的 Codex 登录或模型配置。实验锁定项目依赖，SDK 使用项目内的 Codex CLI，不替换全局 CLI。

解压后，在包所在目录执行：

```powershell
git clone ./最小Agent课程存档.bundle agent-practice-lab
cd agent-practice-lab
git switch -c exercise-tools agent-practice-01-end
pnpm install --frozen-lockfile
pnpm build
pnpm test
```

`exercise-tools` 是自己的练习分支。新建练习分支不会改变课程标签。已有同名分支时使用自己的新名字；保留自己的修改，再切换课程存档。

## 第一阶段：工具读取、保存与读回

起点是已具备业务工具与成熟任务入口的最小源代码。先运行不调用模型的业务检查，再运行一次真实 Agent 任务：

```powershell
pnpm lab init
pnpm lab show
pnpm lab chapter 1
pnpm agent
pnpm lab chapter 1 --output data/读回第一章.json
```

`init` 创建人工编写的用途、设定、要求和单章大纲，拒绝覆盖已有作品。运行 Agent 前，第一章还没有保存；运行后，应从实际事件找到读取当前要求、保存草稿和读回正文，并从独立读取结果确认修订及 `draft` 状态。测试里的人工文本不属于模型写作成果。模型正文和工具顺序会变化；完成条件不是必须重现某个故事段落。

每次任务的输出给出本轮任务标识和记录目录。`runs/<任务标识>/events.jsonl` 是公开事件；`report.json` 对照运行状态与实际保存结果；`chapter.json` 是结束时真实读取的章稿。没有看完整正文，不能根据运行成功判断文学品质。

重复初始化时使用新的数据库，并让后续命令指向同一个文件：

```powershell
pnpm lab init --db data/另一轮.sqlite
pnpm agent --db data/另一轮.sqlite
pnpm lab chapter 1 --db data/另一轮.sqlite
```

如需选择自己的型号或已安装 CLI，在实验仓库复制 `lab.config.example.json` 为 `lab.config.json`，按样例填写 `model` 或 `codexPathOverride`。默认不指定型号，使用正常 Codex 配置。该文件不放认证内容，不需要复制内部认证文件。

## 第二阶段：真实改稿与三章接续

在自己的工作完成并保存后，另建练习分支：

```powershell
git switch -c exercise-continuation agent-practice-02-end
pnpm install --frozen-lockfile
pnpm build
pnpm test
```

可以沿用第一阶段的同一作品，也可以先创建自己的新数据库。仓库 README 和 `docs/三章接续实验.md` 给出 `update`、人工 `save`、`adopt`、`--resume-task` 和 `export` 的具体格式。每次只要求一章；重新读取当前要求与前文，再保存指定章节。要求、目标章节与前文的修订分别作为保存依据。

人工采用是人的具体决定和阅读说明，不由模型评分自动生成。仓库中的编者示例只验证采用入口和接续关系，不表示真实用户认可某份小说的文学品质。接续会话也不能代替重新读取当前资料。

## 第三阶段：资源、提示与插件

```powershell
git switch -c exercise-plugin agent-practice-03-end
pnpm install --frozen-lockfile
pnpm build
pnpm test
```

先有实际作品和已保存章节，再按仓库 README 运行 `mcp:inspect`，读取资源和取得提示。目录存在、实际读取和模型使用是不同结果。提示返回检查方法与材料，不自行调用模型，也不改变人工采用状态。

插件实验通过官方 CLI 临时安装且只读核查。先确认 `novel-practice@novel-agent-lab` 不是自己已安装并在使用的对象；按 README 的 `try/finally` 方式安装、检查、移除这个确切插件。它会临时增加用户配置中的同一插件条目，并由官方移除入口撤销；业务数据库留在自己的实验仓库。不要整体改写用户配置或手工清理全局插件根目录。

Windows 实跑出现过官方移除反馈 `os error 32`。先核对本次检查的归档结果，再重试同一插件的官方移除，并检查插件条目及缓存状态。平台独立的插件数据目录可能仍存在。插件只读核查不等于通过插件完成写作、采用或取消。

## 失败后检查什么

参数格式不符、作品不存在、章节尚未保存和旧修订保存冲突是不同情况。保留工具原始反馈，确认实际请求的作品、章节与依据；旧修订冲突先重新读取，不反复提交同一旧提议。运行结束、失败或取消后，都从真实数据库读取当前正文。运行状态不会自动证明产物存在，也不会自动撤销已经成功的保存。

`node:sqlite` 在 Node.js 24.12.0 中仍是实验性模块。本实验使用本地同步数据库，适合观察小任务的行为，不据此推断大型并发系统的可靠性或性能。
