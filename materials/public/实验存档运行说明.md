## 恢复

在另一个独立目录执行：

```powershell
git clone --branch codex/skill-practice ./项目Skill课程存档.bundle ./skill-lab
Set-Location ./skill-lab
git checkout vcm-08-04-end
pnpm install --frozen-lockfile
pnpm build
```

安装前核对当前目录的 `package.json`、`pnpm-workspace.yaml` 与 `pnpm-lock.yaml`，避免向父项目安装。固定环境为 Node.js 24.12.0、pnpm 11.20.0；Codex SDK / CLI 0.160.0、MCP SDK 1.31.0。宿主沿用正常登录与默认模型选择，本存档不包含登录凭据、用户配置或 `node_modules`。

## 复做范围

完整步骤见仓库内 `Skill练习说明.md`。先执行两次不调用模型的目录预检：

```powershell
pnpm skill:catalog --check-tools --out runs/catalog-initial
pnpm skill:catalog --check-tools --out runs/catalog-isolated
```

以最终 `isolated=true` 和三个读取工具为条件。公开目录生成的本机临时覆盖留在 `runs/`，不写全局配置。已经存在的连接可能与局部 MCP 配置合并，不能只由配置片段推断实际目录；没有隔离成功则不能进入模型实验。

两项真实行为各开始一个新会话，会使用模型额度：

```powershell
pnpm skill:observe --scenario chapter --run-label 独立章节检查
pnpm skill:observe --scenario sentence --run-label 独立单句润色
```

每次创建新的 UUID 目录和 SQLite 数据库，人工样例与资料 r1→r2 更新均在该库里发生。第 1 章已采用 r2；第 2 章草稿 r1 保存于资料 r1、前文 r2。之后资料变成 r2，钥匙归属并未改变。正文很短，只为观察方法，不代表完整篇幅的小说写作。
