## 运行定义

三次都沿固定项目本地 Codex SDK/CLI 0.160.0、MCP SDK 1.31.0 及原 pnpm 锁。Node 与 pnpm 的实际版本、包原件 SHA 另见 `实际依赖与声明核对.json`。只使用当前已有 SDK `startThread/runStreamed(signal)`；文档支持 resume，但本节不新增接续机制或声称新会话含有旧会话记忆。

每次先核本轮 binding、Skill 实际缓存原件、四/五工具实际目录、必要运行契约和正式完整五表。已有前检需要两次：初查保存实际停用覆盖，再确认下一次真实目录。目录 exit0 不代替 isolated/skillsIsolated/memoryIsolated 的实际字段；这些字段只说明该检查定义的覆盖，不表示全部私人上下文已隔离。

维持 sandboxMode=read-only、approvalPolicy=never、webSearchMode=disabled，以及原 runtime 的公开实验覆盖。工具默认 approve 并不意味着人在所有工具前都点击确认；真实人决策在 H1/H2 明确任务对象和具体范围，实际保存记录另核。MCP 服务端写业务与文件环境的边界不同，不解释成“read-only 不能保存任何业务数据”。

库名与运行 UUID 在实施起点时固定，实际 A 命令将采用以下形式，路径中的值须与已建独立库、完整输入和绑定一致：

```powershell
pnpm plugin:observe --db data/changes-本次实际UUID.sqlite --work harness-02f7db59-e6a1-4e9a-8c4d-75adfa2a1fea --chapter 3 --prompt materials/任务-A.txt
```

此处尚不是可执行实际命令，不能把“本次实际UUID”当文件名或冒充已经冻结的实际起点。A `--chapter 3` 表示讨论对象，目录仍只有两章；它不创建大纲或写入任务。H1 增加大纲之后才建立 B 的现有任务目标。

每轮正式命令和完整实际 runtime/threadOptions 在发模型以前交主编。B/C 按真实已经出现的决定分别冻结；不能用目前模板获得对未来未知文字的预授权。每个自然任务内部可能有多次模型请求、多个工具调用，不把三次 turn 说成三次 API。全部用量按 SDK 实际字段记录，不把累计输入当上下文窗口长度。

## 学到什么的判断

学习者应能用真实返回回答：A 是哪个当前资料上的提议，H1 哪个决定进入了资料；B 是否针对该章、以真实基线保存；人的采用与手改实际改变了什么；旧请求为何不能覆盖它；C 在当前稿中改了哪一段、保留了什么。能指出尚未满足的目标，同样是正确的判断，不能靠模型自评分填满通过项。

迁移到代码或表格时，方案对应具体文件/工作表和变更对象，人的选择对应有效范围，保存对应实际补丁或业务写入，验收对应完整差异与当前状态。文件补丁复用成熟 Harness，业务边界仍由现有共享函数承担；不能把小说的 slice 操作教成所有领域通用实现。
