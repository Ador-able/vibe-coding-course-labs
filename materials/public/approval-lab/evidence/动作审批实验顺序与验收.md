# 动作审批实验顺序与验收

本文件在本轮动作审批模型运行之前保存。实验只在独占 action-approval-lab 中操作教学草稿，不采用、发送或发布。原方向选择、人工改稿与会话接续实验保留。

## 固定入口与协议

- AI SDK 7.0.127、@ai-sdk/openai-compatible 3.0.62，TypeScript 独立 CLI。
- 普通百炼配置来自主编授权的 ui-request-review/.env，只由后端读取；不打印、入库、复制或打包 API_KEY。交付仅含空 .env.example。
- 使用原生 toolApproval:{save_draft:'user-approval'}；成熟 SDK 承担生成、审批拦截、拒绝结果与批准后的工具执行。客户端不实现模型执行循环，不直接调用工具模拟批准。
- 复用固定 agent-practice-02-end 的 Store、schema 和业务读取入口，不修改原共享工程或存档。
- messages、完整待决 toolCall、approvalId、具体参数、决定记录和当前状态保存在独占 SQLite。人工 decide 是独立 CLI 命令，只记录决定，resume 才将它交给 SDK。
- 首次 SDK 返回完整 responseMessages 与非自动 tool-approval-request 后才形成待决对象。客户端以真实 approvalId 关联当前对象，不能用一个无范围的 true 放行。

## 场景一：未批准与明确拒绝

1. 初始化教学作品，章稿尚不存在。
2. SDK 实际提出保存动作，返回原生待审批请求，尚未调用 execute。
3. 退出入口，在另一进程 show 读回同一任务、approvalId、完整动作与参数；独立业务 CLI 仍读到章稿 null。
4. 编者通过单独 decide 命令明确拒绝这项动作，保留决定对象和理由。
5. 再 resume，将匹配的 tool-approval-response approved:false 交回 SDK；保留 SDK 的拒绝结果和最终输出。
6. 独立业务 CLI 读取章稿仍为 null；真实 execute 记录为零。不能把模型的“已拒绝”自述当成唯一证据。

## 场景二：已批准但未执行的 A 被新参数 B 替代

1. SDK 实际提出动作 A，保存原 toolCall、approvalId 和完整参数。
2. 编者单独批准 A，只保存这项人工决定，尚未 resume，独立读回仍没有章稿。
3. 编者改变要保存的具体正文/参数，发起 replace。原 A 的参数与人工批准历史保持原样。
4. 原 A 尚未交给 SDK 执行，其决定因这次改变而被撤回；用原生 tool-approval-response approved:false 关闭被替代动作，理由写明“原先批准，随后改变具体动作，原批准未用于执行”。拒绝响应不是把旧 true 直接改给 B，也不是冒称人从未批准 A。
5. 把具体的新要求交回成熟 SDK，得到真正新的 B toolCall 与 approvalId。A 与 B 的调用、请求、参数必须可独立对照，不能就地篡改 A 的 toolCall。
6. 重开入口 show，当前待决对象必须是 B。试用已获批准的 A approvalId 推进任务：入口拒绝旧对象，SDK未执行、业务章稿仍 null；B 的决定仍未批准。
7. 编者明确批准 B，记录这份实际参数；记录决定以后再独立读取，仍没有章稿。
8. resume B，由 SDK 执行 B 的 save_draft，保存返回真实草稿修订。独立业务 CLI 读回正文、修订与状态，全文等于实际 B，而不是 A。

## 验收材料

保留实际命令和进程退出、完整 SDK content/responseMessages/工具结果、人工决定历史、待决对象重开读回、原 A 与新 B 的参数和 ID、旧批准推进失败回执、每阶段独立业务章稿读取与实际执行记录。公开证据不包含网络 Authorization、API_KEY、内部认证或用户历史。

只有各步实际发生并且相互对应，才将本章原生审批范围记为已完成。若模型没有形成原生请求、拒绝后仍写入、参数变化沿用旧请求、或批准以后没有真实执行与读回，保留失败并修复原因，不用官方概述或受控模型输出冒充实测。
