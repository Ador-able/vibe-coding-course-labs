# 控制方式完整实验存档

ZIP 内有 `控制方式完整实验.bundle` 和本说明。Git bundle 包含已有单章业务、五种只读安排、固定依赖锁、十五组对照样本，以及会话结束但材料未取得的两份失败记录和短入口核查结果。不含认证、个人历史、node_modules、SQLite 或宿主会话。

将 ZIP 解压，在解压目录的 PowerShell 执行下面的命令。`D:/ai-labs/control-lab` 是较短的示例目录，可换成你自己的本地短路径。

```powershell
New-Item -ItemType Directory -Path D:/ai-labs -Force
git clone ./控制方式完整实验.bundle D:/ai-labs/control-lab
Set-Location D:/ai-labs/control-lab
git switch -c codex/my-control vcm-06-03-complete
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm compare --case existing --mode serial
```

使用 Node.js 24.12.0 或兼容 Node 24、pnpm 11.20.0，以及前一节正常可用的宿主登录和模型环境。SDK/CLI 固定 0.160.0，MCP SDK 固定 1.31.0，依赖仅在此项目安装。

固定起点 `vcm-06-03-start` 对应 `447d63d0e30f8bc8f0c4807b1138141ab23ba7c9`；固定完成点 `vcm-06-03-complete` 对应 `a51ba09976968e0c323a0c49bfe834b79eb019b2`。当前入口代码的实际模型核查运行在 `21440fb0086d4fb1e0fc5550384c5b9771502d82`；记录以各自 input.json 的代码与配置为准。

保持 `--case existing`，分别将 `--mode` 改为 routed、concurrent、agent、mixed。`--case` 还可取 empty、missing-work；省略参数逐次执行全部十五组，四个作品缺失的应用分支不启动 SDK。每组独立数据库、新线程，已有稿是人工载入的历史真实 Agent 草稿，仍未采用。

每次查看 `runs/control/时间与标识/条件-安排/` 中的完整输入、应用读取、SDK 公共事件和前后业务状态。`sdkState: completed` 只表示会话结束；`materials.ready` 才说明当前目标所需的作品与章稿结果是否都实际取得，仍不证明引用和判断正确。

材料未取得、会话未正常结束或业务内容改变时，命令返回非零退出码，记录仍保存。missing-work 的预期止步因此也返回非零；应查看原始 WORK_NOT_FOUND，而不是把它当成空稿或安装失败。

若工具发现前报告辅助宿主启动失败，先保留本次记录并核对实际入口。较短恢复目录可避免本次观察到的深目录启动问题；它不是对所有此类错误的根因判定。也可通过项目本地 `lab.config.json` 的 `codexPathOverride` 指定已经核对版本与字节的官方 0.160.0 codex.exe 短路径，原工作目录、MCP 程序、只读沙箱及正常认证不变。无需复制登录材料或修改全局设置。

`evidence/04-控制方式对照/` 为实际代码 41d8550 的十五组完整样本；`evidence/05-宿主读取对照/` 保留失败、相同输入的短入口对照及当前入口核查，各自代码、配置和局限均在记录中。不要将 SDK 轮次、工具事件数当成底层模型请求次数，也不以一次结果比较稳定性能。

详细目标、控制顺序和记录解释见仓库 `控制方式实验.md`。Git 恢复代码及跟踪记录，不恢复原业务数据库或宿主会话；模型回答变化时，先核对真实读取与原文，不重复筛选到一个预想答案。
