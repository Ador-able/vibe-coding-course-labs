## 先恢复成独立Git工作目录

在ZIP解压目录里执行。不要把解压目录当作运行目录；不要在Knowledge父库里直接执行观察脚本。

```powershell
git clone --branch vcm-09-09-end course.bundle feedback-lab
cd feedback-lab
git rev-parse --show-toplevel
git rev-parse HEAD
git diff --exit-code
git diff --cached --exit-code
git status --porcelain
```

show-toplevel必须是新建的feedback-lab，HEAD必须等于上面的ac563af完整提交，两个diff退出码都为0，porcelain没有输出。确认后再继续。这样prepare和observe读取的是独立Git版本，而不会取得父库HEAD。

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm feedback:prepare
pnpm feedback:preflight --out runs/local-preflight-01
pnpm feedback:preflight --out runs/local-preflight-02
pnpm feedback:preflight --directory-only --out runs/local-hook-directory
node ../准备本机审核记录.mjs runs/local-hook-directory/hooks.json
```

prepare通过真实人工CLI建立新作品、保存r1和r2、读取完整对象和正文，并记录五表基线。已有data/feedback.sqlite时停止，不覆盖或清库。包内业务数据库是本次实验的记录副本，不能拿它覆盖本机新基线。

MCP预检只建立并归档空会话，不发turn/start、不执行业务工具或Hook。第一轮实际目录如果有额外能力，程序依据已发现目录生成本进程停用项，第二轮检查真实结果；若仍未隔离，请保留失败记录，解决后再审核，不跳过。纯Hook目录只读取定义，不执行Hook，也不发送模型任务。

审核辅助程序只生成approvedBy:null的32文件本机模板。完整阅读当前代码、输入、脚本、精确Hook key/hash和真实隔离目录；本机审核后，才将模板中的approvedBy填为入口约定标志root并另存runs/feedback-trust-review.json。root是本课程审核记录的标志，不是系统账户认证；记录不能代替阅读或实际trusted状态。审核后的文件要保持不变。

首次恢复Git的文本可能是LF，原实验工作字节部分是CRLF。运行时工作字节目录保留29份可以公开的原文件，版本.json分别记录32份工作字节SHA与Git SHA；其中2个全局目录停用清单和它们的私有路径不公开，另有人工五表基线。相同代码的换行差异不能声称原字节相同，新的Hook hash也必须按本机实际目录取得，不照抄旧路径。

## 选择运行时的边界

只有审核完成、实际目录全部符合范围并明确决定使用已配置账户运行一次任务时，才执行以下两步。它们可能使用模型服务；恢复、安装、构建、prepare和此前目录检查没有模型调用。

```powershell
pnpm feedback:preflight --trusted --out runs/local-trusted-directory
pnpm feedback:observe
```

观察器先核32文件SHA、人工r2五表基线、唯一当前Skill、四个业务工具和唯一精确信任Hook，再发唯一一次官方turn/start。不会替模型补写、保存、重试或自动发送纠正反馈。保存次数上限是提供给模型的软约束；取得真实turnId后五分钟请求官方中断，另等待45秒终态，不能当作硬费用上限或停止成功。本轮没有实际触发该中断分支。

实际新增草稿可能不同，请全文检查同一目标、保留位置和事实，不要求复制记录中的措辞。Hook只检查保存返回是否含约定编辑标记，不能评价文学表现；模型shell的read-only不禁止已开放MCP保存，也不禁止已信任Hook记录本实验日志。
