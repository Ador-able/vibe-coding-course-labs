# 保存后的自动检查练习

本包用于学习宿主事件、匹配、真实脚本输入输出、反馈接收与后续行动。小说局部场景是练习材料；本节没有制作执行底座，也不验收完整小说章节。

需要 Git、Node.js 24.12.0 与 pnpm 11.20.0。起点 vcm-08-06-start 为 5bc3d274985350eeb0b4e3a9b0d74e050e121fa6，承接前节插件完成点。完成点 vcm-08-06-end 为 038fec968dd717b522a61669997ca3b3a7aec62e，亦为唯一实际自然任务使用的代码。包内版本清单另外保留批准的工作字节与 Git 字节；CRLF/LF 只按明确的换行规范比较，不称字节相同。

```powershell
git clone --branch vcm-08-06-end course.bundle hook-lab
Set-Location hook-lab
pnpm install --frozen-lockfile

New-Item -ItemType Directory -Path data,runs -Force | Out-Null
```

项目已有独立 pnpm-workspace.yaml、锁文件、成熟 Codex SDK 与 MCP SDK。本节新增定义、检查与公开事件观察；业务 src/mcp.ts 与 src/store.ts 沿用前节实现。项目仍保留前节插件与另一宿主的文件，本次不安装插件、不使用另一宿主。

把包外层“业务数据库/hook.sqlite”复制到自己的新教学路径，例如 data/recorded-hook.sqlite，不覆盖已有作品。

```powershell

```

当前章稿为 r2、draft，要求仍为 r1。r1 与 r2 历史、完整工具参数/返回、Hook 输入输出与 CLI 均在包内。初稿人工片段由 AI 原样保存，业务 origin 为 agent；后续补写由该次真实模型完成，编者没有手工补正文。

原事件有 462 条公开协议消息和 443 条通知，包括六次 MCP 调用、四次 Hook 开始和四次 Hook 完成。正确组两次完成并送入两份实际 developer 上下文，错误匹配组未命中，缺脚本组两次真实 MODULE_NOT_FOUND/退出1/failed。任务仍正常结束，要求未改，r1 历史留存，没有采用草稿。

## 自己准备一次自然任务

在恢复代码后的全新 data/hook.sqlite 初始化：

```powershell
pnpm lab init "seed/门外局部检查.json" --db data/hook.sqlite --work hook-clocktower
pnpm hook:preflight --out runs/check-tools
pnpm hook:preflight --directory-only --out runs/check-hooks
```

不要把已结束实验的数据库复制到 data/hook.sqlite 后再次运行观察入口。它需要一个只有作品要求、没有章节和任务的新状态，不会自动清库。

第一条纯检查关闭 Hook 执行，启动只读目录会话，读取当前 MCP 目录后归档，没有 turn/start。它也取得当前额外服务与方法，准备本进程停用覆盖。第二条只读取 Hook/Skill/配置目录，不启动会话。先看实际 report.json；若 isolated、skillsIsolated、memoryIsolated 不成立，按实际发现处理本进程配置再核对，不直接发模型任务。hooks/list 为空时还要查功能与项目发现，不能只看文件存在。

## 准备本机审核记录

本机 key 含项目路径。以前实验的审核记录只能作为证据，不适用于自己的恢复目录。完成点文件可能按 Git 配置签出为 CRLF，因此要用当前实际字节生成记录。

```powershell
node ../准备本机审核记录.mjs runs/check-hooks/hooks.json
```

这个配套脚本只读取当前目录和文件，写 runs/hook-trust-review.template.json。模板的 approvedBy 为 null，不会被观察入口接受，不会执行 Hook、调用模型或写全局信任。

按模板逐文件完整阅读，特别是两份检查器、运行配置与原始任务。确认三组 Hook 的 source=project、当前 key/currentHash、命令路径与预期效果，再填写自己的人工审核记录。观察脚本约定使用 approvedBy: "root" 作为人工审核完成标志；它是本练习的字段约定，不是账户认证，也不替代实际人工阅读。审核后另存为 runs/hook-trust-review.json。未审核就保留 null，不发送任务。

这份记录中的 hooks.state 整表覆盖只传给本次官方宿主进程，定义精确信任不写入用户全局配置。定义哈希不是检查脚本内容哈希，所以两者都核对。脚本或定义改变以后，需要重新完整检查和记录当前字节，不能只用旧 Hash。

## 官方宿主观察入口

已有合法 Codex 登录与本机模型配置时：

```powershell
pnpm hook:observe
```

观察程序先核对审核文件实际字节、三组精确信任、Skill/记忆范围和仅 novel_lab 四工具。通过后才向官方 app-server 发送一条 turn/start，随后完全由成熟 Harness 选择调用并调度 Hook。程序不替模型调用业务、不手工执行检查器、不实现模型或工具循环、不自动重试。超时仅请求宿主中断，保留失败。

模型沿用账号当前配置。本次实际 gpt-6.1-sol/openai 是记录，不是程序强制选择；新运行可能有实际用量。当前模式 read-only、approvalPolicy=never 不表示 MCP 和宿主 Hook 无写入：前者仍保存该教学数据库，后者仍记录各自 runs。原 Hook permission_mode 为 bypassPermissions，是固定源码中 Never 的名称映射，与跳过 Hook 精确信任不同；本次三个 Hash 均实际 trusted。

两份正确反馈进入后续上下文，r2 确实补写了开门，仍不能据一条任务证明 Hook 独立导致文字改善。自然提示本来就要求补写，三组并发也不是严格对照。检查器只识别占位符，不是完整文学评审。AI 最后没有报告缺脚本失败，并说“未运行检查脚本”；后者仅能指 AI 没有手动运行，宿主实际执行的事实由原事件确认。

实际使用时选择有作用的检查，去掉教学故意设置的错误组，再在当前宿主验证事件、匹配、脚本执行和反馈去向。请保留自己的失败、缺失反馈或未形成 r2 的结果，不自动试到成功。
