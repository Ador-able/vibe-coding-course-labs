# 从本轮材料进入分支和子流程

这份材料配合《分支和子流程怎样保留完整任务信息》。我们用三个完整教师反馈检查本轮范围、字段值、原始类型和真正回传；不评价小说、不改章稿、不发送通知，也不需要模型密钥。

## 先读实际材料

`教学材料/01本轮批次完整输入.json` 是实际唯一业务 POST 的完整正文，顺序为 E02、E01、E03。`教学材料/02含归档项的完整教师目录.json` 另有 ARCHIVE01，它没有进入本次请求。E03 的 `failTask` 是字符串 `"false"`，不能先替它改成布尔值。

`实际记录/` 保留本轮创建、保存、发布、唯一 POST、读回与父子全部节点业务项。`旧单项对照/` 是前面既有的四次单项观察，不是本轮又执行了四次。`教学材料/完整题目提示与答案.md` 和完整方案检查提示可在没有 n8n 的情况下阅读；提示没有请求模型生成答案。

本轮唯一 POST 返回 HTTP200。父执行5、子执行6均为 success/finished:true，一个子执行收到三个完整项。分支分别保存 E01/recorded、E02/classroom_failed、E03/needs_review；合并和回传顺序为 E01、E02、E03。独立表读回也保留三份完整回执，通知状态均为 not_sent。课堂分类未通过和类型待核没有因此变成完成或文学采用。

本轮父回传的 pairedItem 元数据中，E01、E02均为1，E03为2。这份元数据没有逐项证明与原输入位置的对应。本节用 eventId 和完整内容核对实际材料，不据此猜测原因，也不依靠数组位置认人。

## 独立恢复配置

需要 Git 和 Node。绑定脚本只使用 Node 标准库，不安装项目依赖。实际课堂服务为 n8n 2.41.6，固定镜像摘要在 `配置/runtime.json`；本包不包含账户、认证或服务数据卷。可使用前面业务底座的入口，或自己的独立课堂实例。

在解压目录中，从 bundle 克隆到一个尚不存在的独立目录：

```powershell
git clone 本轮原生配置.bundle course-branch-lab
Set-Location course-branch-lab
git switch --detach vcm-11-07-config
git rev-parse HEAD
```

完成点应为 `55af1c10adb32a962139d44c81a67c48310d9bd6`。起点标签 `vcm-11-07-start` 对应 `8c278ffbfb49c283435440b9d0b4c8b318c2be5e`，只有材料与运行条件；完成点增加父子模板、回执表定义与本地绑定脚本。尝试修改时，可从完成点建立自己的分支：

```powershell
git switch -c codex/my-branch-practice
```

`配置/` 是执行前工作树的十个完整文件，bundle 中保存 Git 对象。七份文字文件在 Windows 工作树为 CRLF、Git 为 LF，另外三份原字节相同；`固定配置与字节.json` 分别列出两组 SHA 和长度。恢复 Git 不恢复 n8n 表行、已保存工作流、执行或发布状态。后面的步骤在自己的实例建立新对象，不套用记录中的表或工作流身份。

## 绑定自己的空表、子流程与父流程

1. 在自己的课堂项目新建空 Data Table，按 `receipt-table.json` 建立14列。保留真实表 ID。它是本节完整回执表，不是旧反馈成功表。
2. 把下面的 TABLE_ID 换成新表 ID，生成本地子配置：

```powershell
node bind-branch.mjs --receipt-table TABLE_ID --child-output bound/child.json
```

3. 导入 `bound/child.json` 并保存独立子流程，记录真实子流程 ID。核五项外层输入、严格比较、额外默认输出、Append 三路以及最后的回执保存。发布这个子流程，确认发布已就绪。
4. 把 CHILD_ID 换成刚保存的真实子流程 ID，生成父配置：

```powershell
node bind-branch.mjs --child-workflow CHILD_ID --parent-output bound/parent.json
```

5. 导入 `bound/parent.json` 并保存独立父流程。核入口路径、一次传入全部项（mode=once）、等待开启与五项当前值映射，再发布父流程并确认正式入口就绪。

本次2.41.6实例中，先发布父流程会返回 HTTP400：它引用的子流程尚未发布。先发布子、再发布父后，两者的正式版本就绪。这是实际正式发布的前置条件；不能只看到子流程已经保存就推断父流程可以发布。`实际记录/publish-parent.json` 保留原失败，后续发布和读回各自另存。

本地模板没有真实实例 ID。保存父流程时，服务自动生成 webhookId；实际保存版本和正式版本见 `实际记录/`。不要直接将这些真实历史对象重新导入别人的实例。

## 自己的批次只提交一次

以下命令从 `course-branch-lab` 目录使用包中实际1310字节输入文件。把 URL 换成自己刚确认的正式地址；示例地址是本机课堂入口，不是可共享给别人使用的远程网址。

```powershell
curl.exe --request POST --header 'Content-Type: application/json' --data-binary '@../教学材料/01本轮批次完整输入.json' 'http://localhost:5688/webhook/course-vcm-11-07-batch'
```

本配置向回执表插入行，没有实现重复请求去重；不要为得到同样结果重复提交。读取本包已有记录无需执行这条命令。

进入 n8n 的执行记录，打开这次父流程，从 Execute Sub-workflow 的子执行链接查看入口三项和全部分支。再打开自己的回执表，核全部14列与完整行。按 eventId 找回原反馈，比较正文、作品、章节、读者、名单、版本和真实父子执行身份；originalInputJson 解析后是完整五字段，不是原 HTTP 字节。最后比较子保存输出、父接回和 HTTP 返回。自己的执行 ID、表行 ID、时间不会等于本包中的历史值。

如果创建、发布或运行失败，保留具体返回、已经写入的材料和发生位置；不能将没收到返回当成未执行，也不能用自动重发补成成功。这里没有测试创建响应丢失、并发、空分支、任意字段缺失、运行时异常隔离或长时间恢复。旧单项对照中的 E02 是真实 StopAndError；本轮 classroom_failed 只是保留材料的分类，不抛出这种异常。

## 公开记录的范围

本包中的原件和投影都有自己的范围。九个 REST 记录文件保留业务请求正文、状态与公开响应；两份执行投影保留全部节点业务项、执行身份、时间、源位置与元数据。Cookie、HTTP头、账户/所有者、执行底层编码协议、resume等私有字段没有公开，省略范围在各文件 projection 中标明。它们不是完整私有协议原字节。第三方课件和官方全文只用于研究，没有放入公开包。

`成员清单.json` 列出包中每个其他文件的实际字节长度和 SHA256，清单本身不自引用。既有四项单项实验的原文件与本次材料分别保留，不把旧实验追认为本轮执行。本包没有新的模型请求、通知发送、采用决定或真实使用者验收。
