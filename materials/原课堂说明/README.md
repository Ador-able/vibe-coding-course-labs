# 人工改稿后交还任务

本练习用固定的 Codex TypeScript SDK 0.160.0 接续同一会话，检查 AI 能否重读当前文件，按人的决定交回完整第二章。它沿用课堂《停钟》前文与两份未采用方案；新会话与新材料保存在本目录，不与其他课堂实验混为一次运行。

需要 Node.js 18+、pnpm，以及本机已能正常使用的 Codex CLI 登录。首次按锁文件安装：`pnpm install --frozen-lockfile`。不把登录凭据放进本包。脚本从本地依赖选出固定平台运行包，以 SDK 公开 `codexPathOverride` 使用它；不修改全局配置。

依次运行：

1. `pnpm run wait`。程序复制 baseline 到新的 runs/练习编号/materials，AI 完整读取前文、当前任务与两方案，停下来等待作者选择。保留返回的练习编号。
2. `pnpm run takeover 练习编号`。这是人主动执行的一步，不调用模型。它采用课堂预设的 B 方向，实际在第一章末段添加人物画图并打算下楼的句子，同时保存当前任务与人的决定，写完独立读回。检查 `人工接管记录.json` 的前后全文。
3. `pnpm run continue 练习编号`。新 SDK 对象通过 `resumeThread` 取得待选轮的会话标识，提示 AI 重读实际文件，再交回完整第二章。读 `continue/final-response.md` 全文，并与 `continue/public-events.jsonl` 中完整读取结果比较，不用“已理解”的话替代真实产物。

可以先修改 takeover.mjs 中明确的课堂改稿与任务，再新开一轮练习。不要在本次结果上覆盖失败、重跑选取更好草稿。正文质量与是否采用仍由人决定，脚本不自动判断文学质量。

每一轮保留 prompt、实际材料全文与 SHA256、公开读取事件、最终回答、会话标识和用量。公开日志不保存模型推理内容。未显式指定模型，实际有效模型 ID 不由默认配置推断。

本机已有 node_repl 读取入口可在 Windows 只读 shell 失败后继续读文件；它不是 SDK 默认附带的工具。若当前环境没有可用的文件读取能力，AI 应停止续写并报告；可另用自己能访问文件的 AI 工具完成同样练习。不要因此新造模型循环或把未读取材料的回答认作成功。

待选轮是一轮回答完整结束、任务仍需作者选择，接续是同一会话中的下一轮；不冒充正在运行的工具被暂停并恢复。最终回答由实验记录程序原样保存为独立文件，模型自身只读材料。文件保存和读回不代表小说工作台数据库写入、文学采用或对外发布。本练习没有运行中取消、现实动作撤回或数据库恢复测试。
