# 三章接续实验

## 可运行起点

`agent-practice-01-end` 保留单章模型生成、MCP 保存与实际取消的完整起点。`agent-practice-02-start` 指向同一提交。第二阶段用已有正文扩充资料、改稿、接续到三章，不重新初始化作者的数据库。

独立重复时，先在固定代码上安装冻结依赖、构建和测试，初始化自己的数据库，再用 `pnpm agent` 获得自己的第一章。生成内容可能不同，应完整阅读后自行编写改稿提议。`scripts/prepare-manual-example.mjs` 只记录作者这次真实正文上的具体修改；它会拒绝不含对应句子的其他草稿。

```powershell
pnpm lab update seed/钟楼三章.json --expected-revision 1
pnpm lab chapter 1 --output data/第一章.json
pnpm lab save data/改稿提议.json
pnpm lab adopt 1 --expected-revision 2 --note "写下你对这份正文的实际阅读决定。"
pnpm agent --chapter 2 --resume-task 第一章任务标识
pnpm agent --chapter 3 --resume-task 第二章任务标识
pnpm lab export data/三章草稿.md --output data/导出回执.json
```

资料更新、正文保存和采用分别生成修订。改稿提议需携带 `expectedWorkRevision`、`expectedChapterRevision` 和全部 `expectedPreviousRevisions`；第一章前文为空数组。只有读过相应稿件且决定采用时才执行自己的采用动作。没有决定的后续稿件可以保留 `draft`，导出不会自动采用它们。

数据库与实际导出核对为三章，顺序为 1、2、3，当前正文修订为 3、1、1。第一章保留演示采用说明，后两章仍为草稿；三章的资料与前文修订引用均对应当前状态。程序只核对数量、状态、基线和正文完整性。表达、合理性与创作取舍仍需人阅读。

## 失败与证据范围

对同一数据库再次提交原来的人工改稿提议，MCP 返回 `isError: true` 和 `STALE_CHAPTER`；实际读回的第一章 r3、正文、采用说明与失败前一致。人工测试还验证过期作品资料、过期前文和缺少前章不能保存，以及前文再次修改后导出会指出资料基线已变化。

原始 SDK 事件、输入、运行报告、模型正文、独立读回、人工入口回执、实际过期提议和完整导出保存在 `evidence/02-三章接续真实运行/`。归档脚本只适用于这次真实状态，状态断言不符就停止。模拟文字仅存在于测试；种子资料和编者改稿明确标明人工来源。
