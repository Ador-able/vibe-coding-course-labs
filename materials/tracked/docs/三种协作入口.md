# 三种协作入口观察

本实验使用已有小说业务 Store 和 MCP Server。只新增一个官方 Client 的观察脚本，不调用模型，不安装插件，不改变全局配置。人工短稿只用于观察内容入口，不属于完整小说交付。

在独立项目目录执行 `pnpm install --frozen-lockfile`、`pnpm build`、`pnpm mcp:entries`。环境为 Git、Node.js 24.12.0 或同系列更新版本、pnpm 11.20.0。SDK 固定为 1.31.0；实际协商协议保存在报告和完整公开消息中，不能由当前规范版本反推本轮版本。

每次运行新建 `runs/mcp-entries/<UUID>/`，准备一份人工项目说明及第1章短稿，第2章有大纲但没有保存正文。观察A分别取得资源、读取工具和检查提示，并与独立只读 SQLite 返回的五张完整业务表核对。三种入口取得的是同一份作品说明；提示另有检查方法和当前章稿。观察中不调用保存工具。

随后，已有人工入口更新作品要求为修订2。观察B重新读取资源与提示，对照观察A留下的修订1快照。旧返回不会自动变化。两段只读观察的前后业务内容分别核对；人工更新本身是真实写入，不能把整轮称为没有写操作。

`input.json` 保存真实运行提交、版本、入口摘要和人工材料。`catalog.json` 保存四种目录，`calls.json` 保存每项参数、完整结果及预期错误，`protocol.jsonl` 保存官方 Transport 公开回调中的已解析消息，`complete-objects.json` 保留全部对照对象。五份 `business-*.json` 与 `human-update.json` 用于独立核对状态；报告不代替原件。

第2章的读取工具返回 `result:null`，资源与检查提示返回该章尚未保存的错误；提示漏掉必需章号返回参数错误。它们是固定服务的业务约定，不推广为全部 MCP 服务的统一缺失格式。非预期错误或核对失败时命令非零退出，保留本轮全部记录，再按实际失败环节处理；重复运行使用新 UUID，不覆盖失败。

Git 保存代码、配置、锁文件和已经跟踪的教学证据。切换标签不会恢复忽略的 SQLite、自己的会话或外部业务状态。重新运行会生成新教学库。此实验没有验证资源订阅、宿主自动注入上下文、模型执行提示、Skill加载、远端HTTP或用户取消。
