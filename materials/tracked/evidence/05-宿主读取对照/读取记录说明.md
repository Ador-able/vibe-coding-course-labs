深目录的两次原始代码是 2fee072a43f72378c8111a4a07a338e330d6e86f。SDK 均正常结束，公开事件却没有实际业务工具调用；已有稿组没有取得作品或章稿，混合空稿组只取得应用提供的作品资料。最终回答准确保留“章稿状态未知”。旧版 state 字段不能证明材料齐全。

同输入同字节短入口组使用上述已有稿失败输入、原业务数据库、原 MCP 程序及下载项目的 SDK 模块；工作目录、提示、只读和审批参数不变。唯一显式配置差别为 SDK 官方 codexPathOverride 指向字节相同的 0.160.0 短 CLI 路径。SDK 与辅助程序的路径、版本和 SHA 均在 probe-input.json；新线程和运行时刻必然不同。实际 read_work 与 read_chapter 的完整返回和原 baseline 一致，前后业务状态一致。

这个结果支持短入口解决本次启动失败，不证明 Windows 根因，也不证明所有相似错误都来自路径。原始错误详情只出现在模型最终文字中；公开 SDK 事件没有辅助程序的原始启动错误。不能把模型复述提升为额外取得的底层日志。

核查脚本保留当次绝对路径以溯源；读者应使用项目 compare 入口及自己的短恢复目录，无须复刻作者机器目录，也不复制认证。SDK结束与实际材料核对.json 是用当前材料核查函数对 15 个历史样本和 2 个独立失败样本的核对结果，不是新的模型运行。
