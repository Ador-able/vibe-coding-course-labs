# 接收者任务：登记一份完整教师反馈，再重新打开检查

这是尚未执行的课堂任务卡。输入是教师练习材料，接收者实际操作结果需另行记录；登记成功不代表读者真实读后反馈、AI改稿或文学采用。

## 维护者先填写

| 项目 | 待填内容 |
| --- | --- |
| 维护者与联系渠道 | 待填写 |
| 实例版本 | 自己实例的实际版本；课堂参考为n8n2.41.6 |
| 正式业务入口 | 待填写接收者可访问的实际生产Webhook URL |
| 已发布工作流与版本 | 待填写自己实例的workflowId、发布versionId |
| 任务表位置 | 待填写自己实例的实际表链接/查询方式 |
| 反馈表位置 | 待填写自己实例的实际表链接/查询方式 |
| 接收者账号与范围 | 待说明如何获取自己的账号/只需查看哪些对象；不在文件中写密码 |
| 请求鉴权方式 | 按实际入口填写；无鉴权写“本入口无鉴权”，不要借管理员Cookie代表普通接收者 |
| 输入eventId是否尚不存在 | 提交前按完整身份核查；已有同事件就读回，不覆盖或当新请求 |

表中必要项没填或接收者不能访问，就记录“阻塞”；不要猜维护者的localhost就是自己的服务器，不向课程共用实例投递。接收者可以与维护者共用已约定的演示设备，但必须记实际位置和账号，不能据此证明异地可用。

## 完整输入

在已准备好的独立课堂实例使用文件`接收者教师输入.json`。字段口径沿用479的单项登记流程；维护者应在交付前确认此eventId尚未使用。下面是完整JSON，`false`为布尔值。

```plaintext
{
  "eventId": "course-vcm-11-08-acceptance-01",
  "feedbackId": "FB-vcm-11-08-01",
  "workId": "clocktower",
  "chapterNumber": 1,
  "readerId": "classroom-recipient-01",
  "feedback": "第一章最后的敲击让我想继续读。我还不知道声音从哪里来，请保留这个悬念。",
  "failTask": false
}
```

## 一条完整操作链

1. 接收者用自己的实际账号或已说明无需登录的入口打开材料；记录设备、入口、账号范围和发布版本。下载后打开完整输入文件，确认不是只看到“已生成文件”文字。
2. 维护者给出自己实例的已批准提交方式。接收者只向填写好的正式业务入口提交这份完整输入一次，保存实际响应。不要向仍在监听的测试入口或课程历史URL提交。
3. 以eventId查任务；先记实际received/运行/失败/完成，再查反馈表中的完整正文与身份。202或“收到”不足以写完成。响应未知时先查询同eventId，不根据没有回包就再提交。
4. 若任务完成，在Task任务表核全部七个原输入字段；在Feedback反馈表核eventId、feedbackId、workId、chapterNumber、readerId、feedback这六个原输入字段，以及taskRowId与本次Task的关联。failTask只在Task，不要求Feedback增加这一字段。允许系统增加自己的id与时间，但不得把另一次的任务/反馈当成本次。记录实际executionId及其发布版本。
5. 关闭当前记录页，再从约定入口打开，同eventId读回任务和反馈全文。这仅检验接收端重开后能读回，不冒称重启服务器/恢复原模型运行/并发去重。
6. 若流程宣称通知，到指定接收端查本次消息是否实际出现，并另记提示音/设备条件。这个课堂模板只有not_sent，没有通知步骤；不等待不存在的邀请，不把保存反馈等同通知读者，也不凭无声判断未收到。
7. 用反馈模板分别记功能、辨认、整页口吻，以及失败/阻塞和下一位负责处理的人。不要用一个“满意”覆盖所有判断。

## 本任务怎样结束

- 通过登记任务：实际正式版本执行，完整输入身份/正文保存且接收者重开读回；通知记录如实为未发送。
- 未通过：错入口、错版本、正文/身份缺失、目标表没有本项、失败被当完成或重开读不回。保留具体原件，不为了让表全绿换掉输入。
- 阻塞：账号、分享范围、地址、文件或环境条件尚未满足；记清阻塞发生在输入前还是执行后，指定处理人。
- 本任务未评价：反馈的文学价值、小说采用、真人阅读、外部通知和异地/新设备部署可靠性；这些需要对应接收者与目标任务实际检查。
