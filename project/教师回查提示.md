# 依据原件检查一段资料

下面是给AI的完整教师任务，尚未执行模型调用。它使用本练习读取器生成的完整记录和原文件；没有记录时应报告材料不足，不能运行脚本或补造解析结果。完成读取实验后，可以在具有本地文件读取能力的成熟宿主中使用。

```prompt
请帮我核查一段资料的出处和含义。当前工作目录是本练习的独立lab目录。

先读取public/observation.json与inputs/小说第三章完整原文.txt。JSON中的每份文件都有自己的fixtureKey、docId、fileSha256、parseProfile、pages和异常记录；这些是本次实际记录。inputCatalog中的expectedPhysicalPages是教师预期，不能作为实际读取结果。

我想知道：林澈已经观察到什么？他是否已经确定了钟停的故障原因？后面还保留了哪些需要继续核查的安排？

请先用native-v1的完整三页文字回答。每项判断给出支持它的完整原句和准确位置：文件名、完整fileSha256、parseProfile、physicalPage、blockNo。不要只报文档ID或只取开头；读完第3页，区分观察、未知和后续安排。不要把编者便签当小说情节。

再检查scan-v1在本次记录中取得了哪些页和哪些文字。若有空文本页，给出其原页路径与当前缺口；不能因为搜索“还不知道”没有命中就说文件没有交代。只有实际查看了该原页图像，才可以说从图上读到了什么；如果当前宿主不能读取图片，直接说明无法核查这条途径。没有执行OCR就不要说OCR已经识别。

最后检查native-v2与native-v1的准确文件版本及完整便签。说明哪部分是课堂构造的可见改动，哪部分正文仍相同，不把SHA变化当故事采用或索引已经更新。对broken保留原异常及未知页数，不将打开失败解释为0页成功或材料没有答案。

只做核查，不运行生成器、解析器、OCR、模型客户端或写库，不修改文件。无法定位、页图无法读取、文字或含义仍不确定的地方分别列明。最终返回三部分：有原句支持的判断、未能核查的材料与原因、下一步人工应回查的具体文件和页。不要以自评分或“已经全部阅读”代替这些材料。
```
