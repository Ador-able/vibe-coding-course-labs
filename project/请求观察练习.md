# 取消、超时与失败：受控请求观察

这个入口用两份固定纪要和有限文字，观察官方 AI SDK 的取消、总超时、开始前重试、流中错误及 HTTP 连接中断。它不调用云模型，不读取模型凭据，不写章稿数据库。

## 启动与材料

项目需要 Node.js 24.12 至 24.x、pnpm 11.20.0，以及这个独立项目自己的 Git。依赖以 `pnpm-lock.yaml` 为准，AI SDK 固定为 7.0.122。服务启动前要求工作区干净；在解压目录运行前，应先按完整包的 Git 恢复步骤恢复固定 HEAD，不能借用父目录的 Git。

```powershell
pnpm install --frozen-lockfile
pnpm requests:check
pnpm requests:build
pnpm requests:dev --evidence-dir ../实际证据/自己新建的一轮目录 --port 4340
```

访问 `http://127.0.0.1:4340/requests.html`。记录写入显式指定的目录，每次服务使用新的服务 UUID。结束时在自己启动的终端按 Ctrl+C，不停止其他项目的服务。

`public/requests-fixtures` 保留八份完整材料及原字节清单。服务读取时核对长度与 SHA；两个有限回答通过官方 `MockLanguageModelV4` 交给真正的 `streamText`。每八个 Unicode 码点为一个分段，文字分段间隔 160 毫秒。完整事件、身份及实际时间由本次 SDK 执行产生，不复制旧事件。

A 使用共享书架的历史完整纪要，回答逐字取自历史请求 `1153e17e-e0b4-4870-978f-bf0eca94b0fb` 的第一阶段。“预计接待20人”被写成“限20人”的含义偏差保留。B 的无障碍地图纪要及回答由教师构造。模拟文字不理解自行改动的输入；服务器只接收所选材料的完整原文，其他草稿返回 HTTP 400，页面保留草稿。

## 同一条工作怎样记录

点击主操作先固定当前输入、条件与新的 `requestId`，然后锁定本次操作。当前任务与上次完整结果分别显示材料名称、内容和编号；“下次材料”“下次条件”不改已经显示的对象。三个页面方向只改同一对象的布局，不发新请求。

调用链为：完整输入 → `streamText` 与官方 Mock → `toUIMessageStream` → `pipeUIMessageStreamToResponse` → `DefaultChatTransport` → `readUIMessageStream` → 页面消息快照。SSE 解析与文字快照由 SDK 处理。应用每次替换当前快照，不拼接整份快照文字。

服务端每个请求保存完整参数、Mock 调用、已分配及实际发出的提供方分段、SDK 公共事件、Core 与 UI 回调、UI 事件、产生的 SSE 文字和应用状态。网页记录实际 HTTP 输入、状态、UI 事件、全部快照、异常、人工取消与 GET 返回。不可 JSON 化的信号、流和函数有明确记录标记，流内容另存，不用空对象冒充原因。

这个请求 UUID 是本页的应用身份。服务 UUID、HTTP 观察 UUID、SDK 助手消息 ID、提供方内部调用序号和历史请求 UUID 各有用途。服务端记录只在当前进程的 Map 中，记录文件供观察；服务重启不会从文件恢复原模型调用。

## 七个条件与八次人工主任务

以下是一条复做顺序。各条件只提交一次；手动停止后换 A 是第八次主任务。SDK 内部调用另计，不把内部重试写成用户又提交了一次。

| 条件 | 人工动作 | 核对对象 |
| --- | --- | --- |
| S1：A 正常慢流 | 开始时连续点击，等待完整结束 | 实际 POST 数、当前编号、完整答案与原文的含义偏差 |
| S2：B 开始前模拟 401 | 切换 B 和拒绝条件，明确提交 | 当前 B 输入、无完整新答案、单独保留的旧 A、实际 HTTP 状态与模拟错误字段 |
| S3：B 开始前模拟 503 | 改为有限重试条件，人工再提交 | 一个新主请求中完整的内部调用参数、第一次错误与后续结果 |
| S4：B 手动停止 | 正常慢流收到至少三段非空文字后按停止；人工核查原编号，再换 A 提交 | 停止动作、cancel 回执、SDK 信号与实际终态；旧 B 和新 A 各自完整记录 |
| S5：A 总超时 | 选择总预算 1200 毫秒，等待结束反馈 | 原始超时原因、当时前缀、完整输入；没有自动新 POST |
| S6：B 流中模拟 503 | 收到三个文字分段后消费错误 | 片段、错误、回调及实际内部调用次数，不能凭配置推定接续成功 |
| S7：B 本机 HTTP 中断 | 第三段文字后 250 毫秒由服务销毁当前响应；人用原编号 GET | 页面异常及未确认反馈、服务器 close 与信号、独立读回完整对象 |

开始前的 Mock 错误是 `APICallError` 的 401 或 503 字段，不是云服务请求，也不等于承载 UI 流的 HTTP 状态。共同设置 `maxRetries: 1`，省略 `streamRetries`；开始前有限重试与已发出片段后的接续是不同问题。共同总预算 15 秒，只有 S5 改为 1200 毫秒。用量保持未知，不填历史用量。

S7 实际销毁本机 HTTP 响应，不关闭电脑网络，不证明 Wi-Fi 断开。250 毫秒是教学控制参数，不是历史延迟。若完整结束先发生，保留这次竞态，不重跑挑预设失败。

## 停止、未知和再次提交

“停止本次”先记录人的要求，向同编号的 cancel 入口请求取消仍在运行的 controller，再中止本地 HTTP 消费。回执只说明请求反馈，不能凭按钮或回执宣称模型已停止。提前关闭的 HTTP 连接按本练习策略把信号转给 SDK，原因标记为连接关闭，不替人补出主动取消意图。官方 Mock 配合信号，不证明所有远端模型及时响应或停止计费。

Core `onEnd` 和 UI `onEnd` 是两组回调。完整终态按实际 SDK 完成事件和应用已有错误/取消事实判断；回调出现不认证含义正确、保存成功或人工采用。每条异步处理只更新它自己的对象，仍为当前对象时才更新主面板。

没有可信终态时，主操作变为“核查本次记录”。它只人工 GET 原编号，保留输入与片段；读回仍失败就保持未确认，不自动 POST。确认后，人再决定检查授权、调整预算、改变任务或重新提交。新提交是新编号，不能冒充上一条流继续。

未覆盖的范围包括服务重启后的记录恢复、远端计费、任意网络歧义及有外部副作用的任务重试。请求写文件、发消息或支付时，仍须另核实际作用，不能把本演练的模拟错误结论直接迁移过去。

## 页面比较

原版沿用练习的并列内容面，台面将输入放外围、当前结果放亮面，笔记页连续排列输入与各次结果。比较时保持相同输入、记录、必要操作、数据量、1280×900 或 390×844 视口和缩放 1；切换方向不重新消费请求。实际检查初始、处理中、未完成片段、错误/未知、旧 A 与当前 B、长材料及展开记录。

先看功能与状态是否一致，再看当前/旧对象及下一步是否容易辨认，最后判断字形、密度与面域形成的口吻，并记录损失。并列便于比对，集中面可能使原文更窄，连续页可能增加滚动。这些都要看实际页面，由使用者选择，不预设胜出方向。
