# 依据、保存与检查

## 保存输入

`save_draft` 需要作品 `workId`、章节 `chapterNumber`、完整 `title` 与 `body`，以及本次读取到的资料基线。

| 字段 | 来自哪里 | 本次含义 |
| --- | --- | --- |
| `expectedWorkRevision` | `read_work.revision` | 依据的要求、设定与大纲 |
| `expectedChapterRevision` | 目标章 `read_chapter.revision`，尚无正文时为 0 | 准备修改的正文 |
| `expectedPreviousRevisions` | 前面每章当前的 `number` 与 `revision` | 续写依据的全部前文；第一章为 `[]` |

前面章尚未保存时，不把空白当作已完成正文。前文有新的人工改稿或采用修订时，先读其完整正文，再决定怎样接续。

`STALE_WORK` 表示资料已改变；`STALE_CHAPTER` 表示目标章已改变；`STALE_PREVIOUS` 表示某处前文已有新修订。重读涉及的资料和正文，重新生成或合并提议，不能只换成新的数字再保存旧文本。

## 任务接续

Harness 会话标识用于接续对话；作品、资料修订、章节修订和本轮任务标识属于业务记录。旧任务失败或取消后仍须查询真实产物，区分没有正文、已有保存和结果尚待检查。接续对话不自动刷新数据库内容。

## 检查结果

先查章节数量、顺序、保存状态和资料基线，再对照设定与原文。显式状态或确定事实可直接核对；自然语言矛盾需结合上下文；文学表现需给阅读理由。引用某一句能说明问题，关键词出现不能证明设定得到遵守。

资源返回读取时的当前资料；提示 `review_chapter` 返回取得时的检查方法和资料快照。目录存在不说明客户端已把内容交给模型，取得提示也不代表模型已经检查或人已采用。
