字段口径：
1. 每份输入保留一条记录，不删重复来源。sourceId 对应输入 id；campaignId、date、title 按原文。日期保留 YYYY-MM-DD，标题保留原字符及实际换行。
2. status 只能 observed（已经投放）或 planned（尚未投放）。impressions、clicks、subscriptions 只收已发生的次数；spendCNY 只收已发生的人民币花费。预算单独填 budgetCNY，不填实际花费。所有预期展示/点击不能冒充实际值。
3. 次数用整数，人民币用数值；1千次=1000次、2,000次=2000次。没有材料的数值填 null，明确的0保留0。所有列都出现，不用空字符串冒充数值。subscriptions 是日报中的新增订阅次数，不是跨日报去重人数。
4. duplicateOf 只有原文明说重复转存才填先前 sourceId，其余 null；相同 campaignId 但不同 date 不算重复。同一业务键有互相矛盾的值时应报告，不能静默任选。
5. 每条记录 evidence 为对象，覆盖 campaignId/date/title/status/impressions/clicks/subscriptions/spendCNY/budgetCNY/duplicateOf 十项；每项是完整材料中的一个原文子串，用于回查。原文明确未提供或未投放时引对应原句；没有预算或重复关系的两项可为 null，其他证据不得自己改写。数值可规范化，证据保留原数值和单位。
6. 单独填写 summary：uniqueObservedSourceIds（去除重复后的实际日报）、ctrSourceIds（实际展示已知且>0、实际点击已知的同一组日报）、ctrClicks、ctrImpressions、ctr（小数比例）、knownActualSpendCNY、knownSubscriptionEvents、knownSubscriptionSourceIds、limits。不把 planned 计入实际、不把缺少展示的点击加入 CTR 分子、不把0展示的0/0写成0%。limits 说明不能推出总体、独立订阅人数或标题的因果效果。

只输出一个合法 JSON 对象，无 Markdown 围栏和额外说明。顶层为 records、summary。records 每项固定十一业务字段 sourceId/campaignId/date/title/status/impressions/clicks/subscriptions/spendCNY/budgetCNY/duplicateOf，外加 evidence。不要输出 CSV；CSV 会由独立程序在核对后生成。

- 对每个 evidence 字段连读其本项原文，确认它既是连续原句，又支持该字段的实际值或缺口。预测数字本身不支持实际数值未知；实际未提供应引用原文说明缺口的部分。
