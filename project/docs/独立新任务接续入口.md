# 在独立作品中接续任务

本入口复用成熟 Codex SDK 0.160.0、同一 Store 和已有工作台。教师完整初始作品在 `inputs/heldout/initial-work.json`，首轮完整任务在 `inputs/heldout/A.txt`。B／C 的输入必须从当时实际正文、反馈和人的决定形成；本目录没有替它们预填正文或结果。

数据库使用 `data/heldout.sqlite`，与前置课堂库分开。初始作品没有章节正文。`config/heldout-phases.json` 只预留本轮作品／任务身份、章号、插件版本及工具组合，不能证明业务对象已创建或宿主已采用。

## 开始前

在这个独立 Git 根按现有工作区和锁文件安装依赖，构建当前源文件：

```plaintext
pnpm install --frozen-lockfile
pnpm run build
```

安装与构建不调用模型，但写入本目录的依赖及 dist。初始作品和 A Task 通过现有入口创建，随后准备自有插件绑定：

```plaintext
node dist/cli.js init inputs/heldout/initial-work.json --db data/heldout.sqlite --work heldout-01252847-2f31-4ada-a646-9c0e3d17a327
node scripts/create-lesson-task.mjs --db data/heldout.sqlite --id 7550c45f-0268-483f-8513-9f8a6b2c6be0 --work heldout-01252847-2f31-4ada-a646-9c0e3d17a327 --chapter 1
node scripts/prepare-heldout-binding.mjs --phase A --db data/heldout.sqlite --prompt inputs/heldout/A.txt
```

`prepare-heldout-binding` 调用已有 `prepare-plugin` 检查 Task 并准备 binding，另设置本阶段自有插件版本和工具组合。没有 add/remove、共享配置写回、缓存手工修改或模型任务。它的成功只说明自有源已准备；实际缓存、工具和方法目录要用本轮获准的完整定义检查。

现有 `plugin-preflight.mjs --definition 完整定义路径` 可以检查官方宿主的本轮目录。定义必须取实际官方入口、当前共享摘要、完整五表和自有缓存，不能沿用 07-08 的绝对路径、旧数据库、旧共享摘要或旧批准。`runs/plugin-isolation.json` 和 `runs/skill-isolation.json` 同样只能由当前实际目录确定。启动目录或自然任务须按课堂本轮批准执行；定义没有通过时不发送任务。

## A：保存后停止

实际目录通过后，唯一首轮入口为：

```plaintext
node scripts/observe-continuation.mjs --db data/heldout.sqlite --work heldout-01252847-2f31-4ada-a646-9c0e3d17a327 --chapter 1 --prompt inputs/heldout/A.txt --out runs/heldout-A --stop-after-save
```

只有第 1 章 `save_draft` 的实际成功返回能触发教学停止。观察器不撤回已提交的章节事务；取消记录、章稿及读回分别核对。A 不归档，保留同一个实际 thread。

## B：先让人决定

先完整读 A 结果，再通过当前要求入口保存本轮 H1 资料。把实际 B 请求另存为 `inputs/heldout/B.txt`；不存在完整请求时，绑定入口会失败，不借用 A 提示。创建 B Task 后，使用 B 的四个读取工具和新自有版本准备绑定：

```plaintext
node scripts/create-lesson-task.mjs --db data/heldout.sqlite --id 7dc9bbf4-75d9-442c-b2e5-e20ab3fb9b38 --work heldout-01252847-2f31-4ada-a646-9c0e3d17a327 --chapter 1
node scripts/prepare-heldout-binding.mjs --phase B --db data/heldout.sqlite --prompt inputs/heldout/B.txt
```

在 PowerShell 中从实际 A 回执取得 thread，不能填课堂样例的会话 ID：

```plaintext
$taskA = Get-Content -LiteralPath runs/heldout-A/report.json -Raw | ConvertFrom-Json
node scripts/observe-continuation.mjs --db data/heldout.sqlite --work heldout-01252847-2f31-4ada-a646-9c0e3d17a327 --chapter 1 --prompt inputs/heldout/B.txt --out runs/heldout-B --resume $taskA.threadId
```

B 更新自己的 Task，不改 A 的取消记录；本轮没有保存工具，也不归档。完整实际请求、方法读取、工具返回和答复须分别检查。

## C：依据人的当前改稿接续

完整读 B 后，人才决定优先级、必要的首章修改和当前要求。保存并读回实际 H2 后另存 C 完整请求；旧基线接口反例也依实际 A 请求另外固定，不从示例拼成理想失败。

```plaintext
node scripts/create-lesson-task.mjs --db data/heldout.sqlite --id 43669b1b-fbab-4924-bec6-d7e718c438e4 --work heldout-01252847-2f31-4ada-a646-9c0e3d17a327 --chapter 2
node scripts/prepare-heldout-binding.mjs --phase C --db data/heldout.sqlite --prompt inputs/heldout/C.txt
$taskA = Get-Content -LiteralPath runs/heldout-A/report.json -Raw | ConvertFrom-Json
node scripts/observe-continuation.mjs --db data/heldout.sqlite --work heldout-01252847-2f31-4ada-a646-9c0e3d17a327 --chapter 2 --prompt inputs/heldout/C.txt --out runs/heldout-C --resume $taskA.threadId --archive-final
```

C 的五工具绑定第 2 章 Task。真实保存仍由原 Store 核要求、当前章和前文修订；不允许改首章、采用或发布。只有 C 明确设置 `archive-final`，才在收尾归档传入的自有会话。

## 记录与失败

每轮显式输出目录只创建一次。Task 必须为新创建的 `created`；不重用已运行 Task，不覆盖已有回执，不自动续发。五分钟只报告真实进度，不因耗时自动中断。SIGINT 属于人工停止；A 的保存成功停止属于预先声明的教学停止，两者在实际记录中区分。

完整输入、前后五表、备份、SDK 事件、终态和全文答复均在当轮目录。SDK 事件不能当作逐底层模型请求数；Task completed 不能当作正文采用或文学质量通过。公开交付前须核每条命令与返回的实际内容，排除受保护宿主指令、私有记忆和无关身份；不能把公共字段投影说成全事件原字节。

插件设置与实际缓存属于不同对象。每次切换后，需核自有源、正常版本刷新后的缓存 binding 及真实保存返回中的 Task／thread；旧目录通过不证明后续两轮也已正确绑定。出现真实差异时停止交回，不手工修第三方缓存或向旧库保存。
