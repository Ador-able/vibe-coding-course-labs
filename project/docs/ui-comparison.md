# 用同一业务比较整页

原版、台面和笔记页承载同一作品、章节、正文、必要字段与操作。先保留三个入口，用代表性的完整页面和同一条真实操作链比较。原版可以胜出；删留依据由具体比较和使用者取舍形成。

比较分为三项：

- 功能与状态：是否取得正确对象，保存后能否读回，旧修订、未确认请求和本地改稿怎样处理。
- 信息与操作辨认：在同一视口和缩放下，是否看清当前章节、修订、未保存状态和必要操作。
- 整页审美：字、形、空间、颜色和密度共同形成什么感受，这种口吻是否适合当前活动，又失去了什么。

代码、API数据与静态文件可以支持某些实现判断。它们不直接证明三页的操作体验或整体口吻相同。数据相同不能据此判定两种候选多余，也不能据此断定原版更美。未实际渲染、走过相同操作链或取得使用者取舍时，说明这些判断仍待核查。

需要比较时，保持文案、记录、字段、数据量、必要操作、视口和缩放一致。检查完整正文、长标题以及确实存在的错误、选中、等待和返回状态，避免通过删内容或只展示空页改变比较条件。记录布局或操作步骤的结构代价，不把所有收益归为审美。

当前原型的页面结构见prototype/index.html，交互与数据请求见prototype/app.js，三种方案的样式见prototype/app.css。运行说明见PROTOTYPE.md和README.md。根据本次问题取用这些入口；只读调查不需要为遵循本文件而安装、启动服务或运行完整测试。
