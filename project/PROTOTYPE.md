# 用原型验证真正未知的事

本实验要判断：人能否查看正确的当前稿，保存改稿后实际读回；另一窗口使用旧修订保存时能否保留本地修改，再对照当前稿。页面只突出当前稿件与“保存草稿”。

这里使用真实 HTTP、既有 Store 和 SQLite。`fixtures/three-chapter-archive.json` 是前课完整归档，正文有人工与模型的历史来源；`prototype:seed` 只取其中完整作品资料和三章正文，经 Store 人工初始化到独立 UUID 作品，得到本轮 r1 草稿。它不复制历史采用状态、任务或修订，不是模型新生成。本轮生成的记录不可当成历史运行。

通过条件：完整正文与初始化材料逐字相同；人工保存产生新修订和 `origin: human`；重新读取同一正文；旧窗口保存返回 `STALE_CHAPTER`，当前数据库正文保持；本地改稿仍可对照；网络中断只标为请求未确认，先重读再继续。正文相容性和文学品质仍需人读完整稿件。

HTTP、CLI 和 MCP 复用同一 Store。成熟 Codex Harness 入口保留在 `src/agent.ts`，本节不调用模型，不增加模型循环。官方 MCP Client 能读回保存结果，不代表模型实际理解或使用了改稿。

起点包含可运行的原版；完成点保留原版，并提供左侧组织作品与章节的“台面”、以横向章节和连续文本面组织阅读的“笔记页”。比较前保持相同完整文案、三章数据、字段、必要操作和视口。比较控件统一放在页面外，避免遮住窄屏正文。功能正确、操作辨认和整体口吻分别判断，原版可以保留。原型的结果进入目标与计划；代码是否适合正式产品需要另作判断。

`scripts/observe-reminder.mjs` 是独立教学构造的时间规则实验：反馈后满 24 小时且未暂停时才提示人工处理；新反馈重新计时。它接受明确的 `now`，无需真的等待一天。没有发送提醒，也没有给小说页面增加时间规则。
