# 跨会话推进同一任务

本实验沿用固定小说工作台的 Store、CLI 与官方 Codex SDK 0.160.0。它整理已有三章待审材料，不生成、改写或采用小说，不开发网页。PRD 与计划 B 是教师构造，原三章来自真实历史归档；新 UUID 库由 Store 人工导入为资料 r1、三章 r1/draft。历史任务、采用说明与修订没有搬进新库。

## 先读本轮完整结果

本轮作品为 `4673fae9-27af-45ec-be46-c9fa3675d0e7`，数据库为 `data/stage-4673fae9-27af-45ec-be46-c9fa3675d0e7.sqlite`。`task-state` 含完整目标、完整计划、当前任务、两会话完整输入、实际人工初始化回执，以及会话 B 保存的完整材料核对和最新进度。`deliverables` 含未经 B 重写的三章全文。

`runs/阶段-开始前.json`、`runs/阶段-A取消后.json`、`runs/阶段-B完成后.json` 保留五张表、完整资料与正文及实际文件。两轮目录各含原始输入、全部公开 SDK 事件、全部 AI 文字和运行回执。A 的 `cancel-trigger.json` 保留实际导出完成事件、退出码、完整文件 SHA 与取消时刻。

A 会话标识为 `01a0fde3-9e05-7ea1-89a0-ed976810608b`，B 为 `01a0fde5-0653-70e1-a1a7-1d1045fe0480`。二者都使用官方 startThread；B 没有取得 A 的聊天记录。SDK 的常规项目说明与用户配置仍可能进入会话，不能把新会话说成完全没有既有信息。

A 的完整导出已保存，旧进度未更新，核对文件不存在；取消的 SDK 回合没有 turn.completed。B 从实际 Store 与已存文件判断，逐字核对后复用导出，补齐核对与进度。当前三章仍 draft，人的连续阅读和采用均未发生。取消仅覆盖这一位置，不证明任何中断点都安全，也不证明数据库自动回滚或恢复。

## 不调用模型也可核对保存结果

需要 Node.js 24.12.0 或满足 package.json 的版本、pnpm 11.20.0，以及锁文件中的本地依赖。在此项目目录执行：

```powershell
pnpm install --frozen-lockfile --virtual-store-dir .pnpm
pnpm build
node dist/cli.js show --db data/stage-4673fae9-27af-45ec-be46-c9fa3675d0e7.sqlite --work 4673fae9-27af-45ec-be46-c9fa3675d0e7
node dist/cli.js chapter 1 --db data/stage-4673fae9-27af-45ec-be46-c9fa3675d0e7.sqlite --work 4673fae9-27af-45ec-be46-c9fa3675d0e7
node dist/cli.js chapter 2 --db data/stage-4673fae9-27af-45ec-be46-c9fa3675d0e7.sqlite --work 4673fae9-27af-45ec-be46-c9fa3675d0e7
node dist/cli.js chapter 3 --db data/stage-4673fae9-27af-45ec-be46-c9fa3675d0e7.sqlite --work 4673fae9-27af-45ec-be46-c9fa3675d0e7
```

capture 复用固定 Store 取得完整对象、导出与五表，并检查实际文件；它是观察记录，不替 AI 完成任务，也不代替人的内容判断。SDK 的 SQLite 警告按实际保留。

## 在自己的新编号下练习

若只练习交接判断，可人工或在已登录的成熟 AI 工具中读完整材料，不必再次付费运行。本实验原件足够比较完整导出、较旧进度与接续文件。

若确实要重做两次真实 SDK 会话，先确保此设备现有 Codex 已登录，不把密钥写入项目。准备时另取 UUID 和材料目录；不要覆盖本轮原件。下面命令先仅初始化新库及完整任务材料，没有模型调用：

```powershell
$练习编号 = [guid]::NewGuid().ToString()
$材料目录 = "task-state-$练习编号"
node scripts/prepare-stage.mjs --id $练习编号 --folder $材料目录
node scripts/capture-stage.mjs --folder $材料目录 --output "runs/$练习编号-开始前.json"
```

prepare 只调用固定 seedPrototype 人工导入三章，从 fixtures/task-planning 复制完整 PRD 与计划；任一目标目录或数据库存在就停止，不覆盖。确认新任务范围与完整输入后，下面每条分别产生一次真实模型会话，可能消耗账户额度：

```powershell
node scripts/task-session.mjs --mode A --folder $材料目录
node scripts/capture-stage.mjs --folder $材料目录 --output "runs/$练习编号-A之后.json"
node scripts/task-session.mjs --mode B --folder $材料目录
node scripts/capture-stage.mjs --folder $材料目录 --output "runs/$练习编号-B之后.json"
```

task-session 每次只调用一次官方 SDK runStreamed，消费公开事件并记录，不实现模型工具循环或自造恢复调度。A 在公开 export 完成事件退出 0 且完整文本等于 Store 后发送 AbortSignal；若后续更新已经发生，记录实际状态，不把文件改回“尚未做”。B 调用新的 startThread，从文件和真实 Store 继续。未找到触发条件或运行失败，完整回执保留；不能仅凭脚本退出码认定任务完成。

Git 保存被提交的代码与材料；data、runs 是 ignored，本交付包另外保存本轮实际数据库与记录。checkout 一个提交不会自动重建 SQLite，也不会等同恢复聊天。SDK 会话标识与运行记录用于核对 Harness，会话恢复接口不替代当前业务资料的读取。任务文件中的 P4 进度与 Store.tasks 的小说生成任务是不同对象，本轮后者为零。
