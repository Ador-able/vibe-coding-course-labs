# 逐层读取资料实验

这份文件供运行与独立内容审核使用，不作为 AI 的核对资料。`材料包/` 中的 8 个 Markdown 文件是虚构的教学材料，不对应现有小说产品。`对照摘要.md` 是人工写的、有意省略具体事实的摘要，不是模型实测摘要。

## 固定任务与共同要求

三个条件使用同一个新会话起点、同一模型设置和下列任务，不把上一条件的答案带入下一条件。保留项目现有登录方式，不读取或复制凭据。SDK 与其运行时采用项目已锁定的 `@openai/codex-sdk@0.160.0`；不覆盖为本机全局 alpha。只读、关闭网页搜索，均不修改资料。

```text
为第4章开头核对一句话：“林澈取出档案原件，用‘青鹭’称呼南城联络人。”判断哪些表述可以采用，哪些需要改动或向作者确认。只做用料核对，不写正文，不修改文件，不引入后续章节尚未采用的身份设想。

只根据本轮允许使用的资料判断，不补造事实。资料的采用状态以明确的人类决定为准，日期更新不代表已经采用。请说明每项判断的依据：实际得到的资料、版本和具体位置；不能确定的部分说明缺少什么。
```

共同要求只是采用规则和证据要求，不预告实验中的答案或冲突位置。

## 三个条件

1. 全部提供：在共同提示后直接放入 `材料包/` 全部 8 个文件的路径和全文。明确本轮资料已随提示提供，不执行命令，不另外读取文件。检查回答把哪些信息当成采用依据。记录为“全文已提供”，不能伪称观察到了文件读取工具调用。
2. 只给摘要：在共同提示后只放入 `对照摘要.md` 的全文。明确本轮只能使用这份摘要，不执行命令，不读取其他文件。回答承认信息不足是正确处理证据边界，不需要故意让它猜错。
3. 逐层读取：本轮只提供共同任务、只读资料包的实际路径和 `入口.md` 入口，不提前把详细规则、资料索引或正文放进提示。要求先读入口，按任务需要打开相关文件，汇报已读、未读及不足。记录 SDK 公共 `command_execution` 完成事件的 `command`、`aggregated_output`、`exit_code`、`status`，核对实际返回的内容及有无失败、部分返回；同时保存最终答复和 `turn.completed`。不以代理的“已读完”代替工具返回内容。

材料不变，披露方式变化。这个小实验检查信息是否足以支持判断，不证明哪种方式在所有任务中质量最高、速度最快或实际价格最低。三次运行的原始提示和最终答案都要保存；出错或未完成要如实记录，不把中断当成正式结论。

## 资料与预期证据（供审核，不提交给实验会话）

- R01：用料规则 v1，正式采用。采用状态、角色知情范围、正式资料冲突需作者确认。
- N01：人物卡 v2，正式采用。第4章持有物是复印页，原件留在北城档案室；称呼是“枫灯”。
- N02：第3章 v1，正式采用。结尾第一段确认复印页与原件的位置；结尾第二段称呼是“青鹭”。
- N01 与 N02 的称呼表述冲突。它们属于不同文档，不能依据 v2 大于 v1 或日期更近决定人物卡覆盖前文；没有人类指定采用顺序，不能自行编造更名、双代号或已经确认的解释。
- N03：较新的第4章试写，未采用。不能用其中的原件覆盖正式资料。
- N04：第5章方向，未采用。其身份设想不应进入第4章的核对结论或正文。目录只标用途和状态，不能把未采用身份写入索引摘要造成提前泄漏。
- N05：港口背景，正式采用。与本次持有物和称呼核对无关；如果任务改成描写港口，它才可能需要读取。未读不是缺失。

只给摘要条件没有具体持有物、代号与原文位置，不支持确定“原件”能否采用，也不支持确定称呼；应说明需查正式人物卡与第3章。逐层读取条件正常可先取得入口、规则、索引，再取得两份正式原文；不是要求严格五次命令、固定工具次数或全部扫描。

## 独立核对

1. 核对资料清单的逐文件 SHA-256 与执行前后实际字节一致。
2. 检查三个条件确为不同的新 thread，未复用同一会话历史，实际配置和运行时版本记录一致。
3. 检查摘要条件没有执行额外读取；全文条件使用的确是完整 8 文件输入。
4. 对逐层读取，逐条回看公共完成事件与返回内容：定位入口、规则、索引、N01、N02；若缺读、失败或部分返回，按实际证据判断，不自动补齐。
5. 分别核对复印页、正式称呼冲突、人类决定、未采用资料与后续身份边界。保留运行中多读、少读或错误选择的真实记录。
